## 1. The arrangement, and whether the merge held

The merge held, and it was tested against the real workbench BEFORE building
on it. Every section of the current `_build/workbench.md` lands on a route
graph node, and the ledger's own leaves corroborate the hand-written notes:

| Workbench section | Where it landed on the graph | The ledger agrees |
|---|---|---|
| DISPATCHED NOW ("nothing. All slots free") | position marker on the "a slot is free" start node | the start node is exactly the free-slot state |
| QUEUED ("Bridge's 50 s tail <- READY", "the frozen mathematics <- D30 lifts") | attached to the "is D30's freeze lifted?" decision node | the freeze gate is the release condition both items name |
| CONDITIONS, tail items | attached to the exit-condition node ("tail profiles flat -> freeze can lift") | the exit condition is the campaign's "until it holds" edge |
| CONDITIONS, lever item ("a lever's region is opened by ruled work -> take that lever") | attached to the TAKE IT NOW outcome | that outcome already says "marginal cost is near zero when the file is already open" |
| NOT DISPATCHING, waiting levers | attached to KEEP AND WAIT | the leaf chips are the same four levers the note names |
| NOT DISPATCHING, B-condensation-story | attached to NOT A ROUTE | the leaf chip is B-condensation-story, status REFUTED |
| NOT DISPATCHING, D-order-core | attached to RE-PRICE FIRST | the leaf chip is D-order-core, status PARTLY SUPERSEDED |

So the strong move from the brief was not a forced merge: the two panels
really were one thing seen twice. The route is the decision procedure, the
workbench is where the orchestrator stands inside it. The result is one wide
panel, "The workbench route: where we are, what happens next, what would
change it", and the page reads top to bottom as:

1. The workbench route (wide): the flowchart with the position marked, the
   queue on the freeze decision, the conditions on the nodes they change, and
   the not-dispatching rows on the lever outcomes. Everything the orchestrator
   writes by hand is attached to the node it belongs to; anything that cannot
   be placed renders verbatim below the graph. The generated corroboration
   (task index IN PROGRESS rows, newest briefs, the owed table, the lever rows
   with cost/net/risk) stays under the graph, so the merge loses no
   information either panel carried.
2. Remaining lines (half width) and cold-start seconds (half width) side by
   side: the two distributions are the second thing a reader wants, and they
   sit at the same height instead of one above the other.
3. Code hierarchy (wide): the deep reference at the bottom.

The old one-dimensional stack (workbench, route, lines, seconds, hierarchy,
each a full-width list) is gone. Implementation: `build_route` carries anchor
keys on the nodes (`scripts/dashboard.py:184`), `render_route_node` renders
attached workbench content inside the anchored node
(`scripts/dashboard.py:374`), `place_workbench` does the section-to-anchor
mapping with an absolute verbatim fallback (`scripts/dashboard.py:1292`), and
`panel_workbench_route` builds the merged panel (`scripts/dashboard.py:1390`).
The page order is set in `render_page` (`scripts/dashboard.py:1551`).

## 2. The charts

Both charts are inline SVG generated in Python (an arc is polar-to-cartesian
arithmetic, `pie_svg` at `scripts/dashboard.py:841`; no library, no script,
no network). Every pie labels its absolute total.

### Line distribution (panel_lines, `scripts/dashboard.py:921`)

Two pies, one per caliber, side by side. A slice is the measured standing
(18,464, from `scripts/ledger.py --brief`) plus each remaining row's band
MIDPOINT, because a band is a range, not a point. The panel says exactly that:
"angles use each remaining row's band MIDPOINT: the rows are ranges, not
points ... and standing is measured while remaining rows are estimates, so
these proportions are a reading aid, not an exact statement." The bands ride
in the legend and in the unchanged table below.

Tail rule (`remaining_pie_slices`, `scripts/dashboard.py:797`): a row stays
individual when its midpoint is at least 8 percent of the remaining total,
capped at six rows and floored at four; the rest group into one tail slice
that names its members.

Naive pie, total 28,066 lines (= standing 18,464 + remaining midpoints
9,602): standing 18,464 (66%), W3 1,850, stepinl-rewrite 1,485,
carried-sequence 1,350, W1p 1,210, w7-residue 985, retirement-surgery 895,
and the tail of 3 smaller rows, 1,827 (gch-proof-steps 750, structural-story
602, choice-rehome 475).

Calibrated pie, total 39,391 lines (= standing 18,464 + remaining midpoints
20,927): standing 18,464 (47%), W3 5,450, W1p 3,450, carried-sequence 2,950,
w7-residue 2,075, stepinl-rewrite 1,930, gch-proof-steps 1,700, and the tail
of 3 smaller rows, 3,372 (choice-rehome 1,425, retirement-surgery 1,165,
structural-story 782).

The pie total is deliberately different from the endpoint bands in the stat
cards above (24.95-31.18k naive, 31.60-47.18k calibrated): the note says what
the pie total is (standing plus midpoints) so the two readings cannot be
confused.

### Seconds distribution (panel_seconds, `scripts/dashboard.py:988`)

Current-check pie, total 1,099 s ([timing].full_cold_seconds): L.Rud.Bridge
199 s (18%), L.Condensation 142 s (13%), L.Ordinal.SquareLaw 64 s (6%), and
"everything else in the profile" 694 s (63%), which is 1,099 minus the three
named hot modules. The note says these are profile-instrumented seconds and
that the profile-to-wall ratio is not pinned (0.6-0.7 per the timing note).
If the named modules ever sum above the recorded full check, the panel says
so and draws no "everything else" slice rather than inventing a negative.

Tree-cost pie, total 2,724 s, drawn SEPARATELY and labelled PRE-FIX: surviving

rows are the pre-fix profile (the 2,723 s the timing note records, within

## 4. The fallback under a drifted workbench

`place_workbench` returns (placed, unplaced); every unplaced item renders
verbatim under "Hand-written workbench text that could not be placed
(verbatim)", and when the ledger is unreadable the WHOLE hand-written file
renders verbatim instead of the graph. The "Last written:" preamble stamp is
treated as metadata and shown in the panel note, not dropped.

Deliberately malformed input exercised end to end (an arrow item with no
queued relation, a queue item with no arrow, a condition with no keyword the
matcher knows, an unknown heading the parser never saw, and a NOT DISPATCHING
row with no keyword):

```
Last written: 2026-08-06, after executing [T115]'s audit.

DISPATCHED NOW
  one dispatch is running: the T117 build.

QUEUED, AND WHAT RELEASES EACH
  an item whose arrow is broken -> this has an arrow but no queued relation
  a wholly new kind of queue item with no arrow at all

CONDITIONS THAT WOULD CHANGE WHAT I DISPATCH
  the fuel gauge reads empty   -> nobody can tell what this condition means
  a lever's region is opened by ruled work -> take it now, cheapest first.

NOT DISPATCHING, AND WHY
  K-something      a row with no keyword the matcher knows.
  B-condensation-story      refuted by [T84].

A BRAND NEW HEADING THE PARSER NEVER SAW
  line one under the unknown heading
  line two under the unknown heading
```

Result (checked line by line, escaped the way the renderer escapes):

```
MISSING LINES (escaped comparison): none
stamp shown in panel note: True
unplaced block present: True
fuel gauge condition verbatim in unplaced: True
unknown heading lines preserved: True
position marker: True
self-contained: True True
```

So a drifted file loses nothing: unmatched conditions and unknown headings
appear verbatim in the fallback block, and the unknown heading's lines ride
inside the section they drifted into rather than vanishing. The existing
`test_workbench_drift_fallback` (`scripts/tests/test_dashboard.py:378`) still
passes unchanged.
