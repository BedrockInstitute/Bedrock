## 1. Resolutions of the gate's ambiguities, by the delivered code

1. **`orderAt (sucV C₀) o` / `relOf`.** T14's T2/T3 write
   `relOf (orderAt (sucV C₀) o) a b`. `orderAt`/`relOf` are the *retiring*
   cone's names ([Choice/Step.lagda.md](/Users/alsg/Agentic/Bedrock/src/L/Choice/Step.lagda.md)
   :740-741, :233-234). Over the delivered face the gate names
   ([Order.lagda.md](/Users/alsg/Agentic/Bedrock/src/L/Rud/Order.lagda.md)
   :838), the analog is `Sset-order (sucV C₀) ordS` whose relation is
   `Sset-below (sucV C₀) ordS : Member (sucV C₀) → Member (sucV C₀) → Type`
   (Order.lagda.md:1026-1028, :835-836). Every "comparison" below is
   `Sset-below (sucV C₀) ordS`, and `Member α = Σ[ x ∈ S ] ⟨ x ∈ˢ Sset α ⟩`.
2. **The concrete level.** T2's carrier constant `C₀` was abstract
   ([ProbeFace.agda](/Users/alsg/Agentic/Bedrock/src/ProbeFace.agda):38). The
   gate fixes "one concrete level" and needs `IsOrd` to instantiate the
   delivered order. The unique closed ordinal whose previous level is empty
   is `∅` (`∅-ord` is a theorem,
   [Ordinal.lagda.md](/Users/alsg/Agentic/Bedrock/src/L/Ordinal.lagda.md)),
   so this probe runs `sucV ∅` with `u = Sset (sucV ∅)` and
   `Sset (sucV ∅) ≡ step (Sset ∅)`
   ([Hierarchy.lagda.md](/Users/alsg/Agentic/Bedrock/src/L/Rud/Hierarchy.lagda.md)
   :410-411). At this level the successor clause IS the whole order (nothing
   is old), and every stage-`∅` producer's arguments are the self `∅` (a
   member of `Sset ∅ = ∅` is impossible), so the argument lex has no cases:
   the new-before-new clause is total and there is no recursion into the
   previous-level order. At any *higher* concrete level the clause is not
   total (old members exist), and at an *abstract* carrier the formula
   content is incomplete for the same reason. This is recorded as the D-10
   correction beside T14's T1/T2 (§3).
3. **The formula's constants.** The image sets `im i (Sset ∅)` are *not*
   members of the level (a member of `step u` is a member of `u' u` or a rud
   *value*; the image set is neither), so the sigma_< formula cannot use them
   as constants. The formula must name the concrete *values* `Fof i ∅ ∅` and
   state the least-producer conjuncts as negated value equalities. The
   meta-level lemmas need no image-set membership at all: everything rides on
   value equalities `x ≡ Fof i ∅ ∅` (the `keyNotInI`/`keyImgVal`/`keyOpEq`/
   `keyOpGt`/`selfLtImage`/`imgLtImg` machinery was written and is the
   correct content, but is walled at check time, §4.3-4.4).

## 4. The walls, measured, by LESSONS class

Each wall was reproduced in isolation with a minimal repro file (bisect
protocol, one process, `GHCRTS=-M8g`); "hang" means the process did not
finish within the observation window (30 s-10 min) and the full-file runs
ended in heap exhaustion at 8192 MB.

### 4.1 The concrete presentation wall (P-series: concrete-tower normalization)

- `fiber u ∅ ∅∈u .fst` and `fiber u (Fof i ∅ ∅) mem .fst` with
  `u = Sset (sucV ∅)`: hang in isolation (> 30 s; the full first attempt
  exhausted the 8 GB heap after ≈ 8 min). The same machinery at an abstract
  carrier (ProbeFace ArmB, `⟪ Sset C₀ ⟫` with `C₀` a module parameter) is
  instant. The index type `⟪ u ⟫` is the monic-presentation quotient of the
  concrete tower level; forming a member's fiber normalizes it.
- Module telescope `(c∅ : ⟪ Sset (sucV ∅) ⟫)` with later content: hang. The
  concrete index type in a module parameter poisons every later definition's
  elaboration.
- This is the wall class the retiring cone's seals exist for:
  [Choice/Order.lagda.md](/Users/alsg/Agentic/Bedrock/src/L/Choice/Order.lagda.md)
  (an element reaching a satisfaction slot is unfolded by conversion on
  every read; the seal stops that). It is a P-class engineering wall, not a
  mathematical one: the members exist, only their indices are unformable
  within budget.

### 4.2 The key-shape case analysis (P-series: least-element search normalization)

- `with memberKey (sucV β) ordS (x , hx) .fst` with a trivial body: hang,
  at the concrete level **and** at an abstract carrier. Case-analyzing the
  key normalizes `memberKey = leastTrace = leastOf`, the least-element search
  over the delivered well-order; the search does not reduce to a case split.
  The with-case on a *variable* trace (`with k .fst`, `k : Trace`) is
  instant, so the wall is the search, not the data type.
- Comparison types carrying the concrete Ord `(β , ordβ)` (e.g. `k .fst ≡
  prod-self (β , ordβ)`): hang; the same statement with a variable Ord is
  instant.
- Consequently the comparison lemmas (`selfLtImage`, `imgLtImg`, `keyOpEq`,
  `keyOpGt`, `keyNotInI`, `keyImgVal`) — whose *content* is correct — cannot
  be checked at the delivered face, and the delivered trichotomy
  (`prod-tri`/`traceTri`/`ordTri` at the concrete ordinal) is in the same
  wall class.

### 4.3 Not the P-d wall

The P-d wall (hProp paths between satisfactions of concrete formulas,
[LESSONS.md](/Users/alsg/Agentic/Bedrock/dev/LESSONS.md):93) was *not*
reached: the satisfaction types could not be formed (§4.1-4.2), so no
path-former measurement was possible. The direction-pair discipline was
followed in everything that did check (§2), and the discarded comparison
lemmas were written as direction pairs, not hProp paths. The walls that fired
are a different P-series class (concrete-tower presentation and
least-element search normalization), which this report records as the
