## 3. What actually cleared each wall

### Wall 2: dissolved by reshaping the bounded-quantifier clause (P-i [E])

r3a's `∃̇∈` clause ranged the image over **the bound**: `⋃ img(f, bound)`. That
forces `bound ⊆ u` (to lift a witness `z ∈ bound` into `u`), hence
`⟨ eval c (map fst ws) ∈ₛ u ⟩` for the bound's composite, hence a transport whose
motive is membership in a value produced by the composite evaluation. That is
wall 2, and it is *generated by the clause design*, not by the checker.

The tree's inner satisfaction already restricts its quantifiers to members of
`u`: `satN (∃̇∈ t φ) γ = ∃[ m ∈ ⟪u⟫ ] (⟪u⟫↪ m ∈ₛ tmVal t γ) ⊓ satN φ (ι m ∷ γ)`.
So range the image over `u` itself and apply the bound as a *test inside the
family*:

```
{x ∈ u | ∃ z ∈ bound. φ(x,z)}  =  ⋃ { {x ∈ u | w ∈ bound ∧ φ(x,w)} : w ∈ u }
```

The test is one composite per term view (`boundComp`: characteristic separation
when the bound is x-free, collection when the bound is the separated variable).
No `bound ⊆ u`, no `termC∈u`, no transitivity, no transport. The whole `split`/
`semSplit`/`valSem`/`valSplit`/`eval-cong`/`inl-inj`/`inl-inr-disj` kit that
r3a built to state and dispatch `termC∈u` is gone with it.

Side effect: **`tu : Trans u` is no longer spent by the walk.** It is kept as a
module parameter for the operations layer, but the realization is transitivity-
free. Flagged for the owner as an interface question.

### Wall 1: the statement's index, and the term view

Two changes, both [A]/[C′] in kind:

1. **Member-indexed statement over `SM`, not over `⟪u⟫`.** The characterization
   now reads
   `(ws : Vec SM k) (x : SM) → ⟨ fst x ∈ₛ eval c (map fst ws) ⇔ₚ Sat φ (ws ++ x ∷ envρ ρ) ⟩`.
   `SM = Σ[ v ∈ V ℓ ] ⟨ v ∈ u ⟩` is the restricted carrier the environment
   already needs, so (a) the endpoint is `fst x`, a projection of a **variable**,
   with no presentation machinery in the type at all, where `⟪u⟫↪ m` is an
   application of the deep-monic-presentation eliminator; and (b) the
   `x ∈ₛ u` conjunct of the probe's statement is *carried by the index type*
   (`snd x`), so it never appears in an obligation. `uSepD` discharges it once,
   for every clause, from any separation-shaped operation spec.
2. **A three-constructor term view `TmC` (`free (fcon v)` / `free (fvar j)` /
   `sep`) with a cheap codomain** (P-i [C′]), replacing r3a's `Comp k ⊎ Unit*`.
   Because the x-free cases share a composite (`fcomp`), the atom grids are
   2x2, not 3x3 or 4-with-equations, and every clause is one `uSepD`
   application with **no transport at all**. The single term-level bridge
   (`tval-ok`) is stated once, at the top, and travels into the clause through
   the neutral `⇔-∈ₛ` / `⇔-∼` helpers, whose endpoints are variables
   (case-14 discipline). The view's weakening (`wk`) and its value law
   (`wk-tval`) are three `refl` clauses, because `map fst` makes
   `lookup (suc j) (fst w ∷ map fst ws)` compute.

### The unification fix (run A → run B), likely the wall's real engine

Run A is run B with one change: the `⇔`-composition and membership-transport
helpers took their endpoints as implicits over `hProp ℓ`
(`{A B C : hProp ℓ} → ⟨ A ⇔ₚ B ⟩ → …`) and over `V ℓ` recovered from a
membership (`{b : V ℓ} … ⟨ a ∈ₛ b ⟩`). Neither can ever be solved: Agda would
have to invert `⟨_⟩` (a projection) applied to a *defined* function
(`_⇔_`, `_∈ₛ_`). Agda does not fail immediately; it **blocks the constraint and
keeps normalizing**, and the dump names exactly the `V`-presentation
eliminators (`elim`, `sett-repr`, `dmp`, `isPropDeepMonicPresentation`).

The cure is to state every combinator over the **carriers**:

```agda
_↔_ : Type ℓ → Type ℓ → Type ℓ
A ↔ B = (A → B) × (B → A)          -- definitionally ⟨ A' ⇔ₚ B' ⟩
⇔-trans : {A B C : Type ℓ} → A ↔ B → B ↔ C → A ↔ C
⇔-∈ₛ : {a a' b b' : V ℓ} → a ≡ a' → b ≡ b' → (⟨ a ∈ₛ b ⟩ ↔ ⟨ a' ∈ₛ b' ⟩)
```

Now every implicit is solved from a **path** or from a **Π type** (both rigid),
and `⟨ A ⇔ₚ B ⟩` is still the readable form used in every signature, because the
two are definitionally equal. Same for `identityPrinciple`, whose `{a} {b}` must
be given explicitly whenever it is used *toward* an `⟨ a ∼ b ⟩` rather than from
a path.

**Hypothesis (evidence: run A's dump; not a controlled reproduction of r3a's
hang):** this is the engine of r3a's wall 1. r3a's nine shapes all kept the
presentation eliminator (`⟪u⟫↪ m`) in the obligation type; a blocked implicit of
this class then retries against ever larger normal forms of that eliminator,
which is a hang rather than an error, and it is context-dependent (hence
"in situ only, never in isolation", the B4e signature). The two cures compose:
remove the eliminator from the type (change 1) *and* leave no blocked implicit
(the unification fix).

## 6. Interface change the Ops layer must know about

**`imgOp` gained the witness stack.** The delivered r3a telescope had

```agda
imgOp : {k : ℕ} → Comp k → V ℓ → V ℓ          -- ws dropped
imgSpec : … z ≡ₕ eval f (y ∷ ws) …             -- for EVERY ws
```

which is not satisfiable: `eval (imgC f a) ws` must be
`{ eval f (y ∷ ws) : y ∈ eval a ws }`, and that depends on `ws`. Any Ops-layer
construction would have been unable to instantiate it (and any consumer could
have derived that the family is constant in `ws`). Fixed to

```agda
imgOp  : {k : ℕ} → Comp (suc k) → Vec (V ℓ) k → V ℓ → V ℓ
imgSpec : {k} (f : Comp (suc k)) (vs : Vec (V ℓ) k) (p z : V ℓ)
        → (⟨ z ∈ₛ imgOp f vs p ⟩ → ⟨ ∃ₚ⁺ (λ y → (y ∈ₛ p) ⊓₂ (z ≡ₕ eval f (y ∷ vs))) ⟩)
        × (⟨ ∃ₚ⁺ (λ y → (y ∈ₛ p) ⊓₂ (z ≡ₕ eval f (y ∷ vs))) ⟩ → ⟨ z ∈ₛ imgOp f vs p ⟩)
```

This is inside Realize's own telescope (no other file touched), but the R1/R3
assembly must supply the stack-indexed form.

## 9. Lesson candidates, with measurements

1. **(new, P series) An implicit that must be inverted through `⟨_⟩` is a
   blocked constraint, not an error, and it normalizes the `V`-presentation
   machinery.** State every bidirectional combinator and every membership
   transport over the **carriers** (`_↔_ : Type ℓ → Type ℓ → Type ℓ`, implicits
   solved from paths and Π types); `⟨ A ⇔ₚ B ⟩` is definitionally `⟨A⟩ ↔ ⟨B⟩`,
   so the readable hProp form survives in signatures at zero cost. Measured:
   run A 27 s failing with the dump naming `sett-repr`/`dmp`/
   `isPropDeepMonicPresentation`, run B 18.4 s green, single change.
   Corollary: `identityPrinciple`'s `{a} {b}` must be explicit whenever it is
   used toward `⟨ a ∼ b ⟩` rather than from a path.
2. **(new, D or P series) State a subset-of-`u` characterization at the
   restricted carrier `SM`, never at `⟪u⟫` with `⟪u⟫↪`.** The index type
   carries the membership certificate (so the `x ∈ u` conjunct never enters an
   obligation) and the endpoint is `fst x`, a projection of a variable, so the
   presentation eliminator never enters an obligation type either. Measured:
   the r3a m-indexed shape >240 s in situ across nine formulations; the
   SM-indexed shape is part of an 18.4 s file with a 0.27 s hottest clause.
3. **(new, P-i [E] instance) A bounded quantifier over a transitive `u` ranges
   its image over `u`, not over the bound.** The inner satisfaction already
   quantifies over members of `u`, so the bound becomes a test inside the
   family and the clause owes no `bound ⊆ u`, no transitivity, and no
   membership-over-composite-value transport. Measured by dissolution: r3a's
   wall-2 obligation does not occur in the delivered proof; the entire
   `termC∈u` support kit is deleted.
4. **(amendment to P-h, measured counter-instance)** Face abstraction is not a
   cure for a conversion wall by itself. Same proof, abstract face 18.4 s,
   concrete face 14 s. P-h's trigger is a conversion problem that *forces* a
   heavy head to normalize; when every step through the heavy layer goes
   through a read stated at variable arguments, the trigger is absent and the
   abstraction is insurance, not medicine. Keep P-h as doctrine, but price the
   insurance and do not attribute a cure to it without the A/B.
5. **(craft) The `map fst` formulation of the witness stack makes the term
   view's weakening law three `refl` clauses**, because
   `lookup (suc j) (fst w ∷ map fst ws)` computes to `lookup j (map fst ws)`.
   r3a needed `lookup-map` and a `valSplit-suc` chain for the same fact.
