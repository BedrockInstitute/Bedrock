## Method notes

- The D-10 in-place verification mattered: the first attempt to measure HF
  "before" by swapping the pre-fix `Bridge.agdai` back into the cache did
  **not** work. Agda 2.8.0 validates an imported module's interface against
  the current source and re-elaborated Bridge (200 s) because the swapped-in
  pre-fix interface no longer matched the post-fix source (the copied
  interface's mtime was newer than the source, so a pure mtime check would
  have accepted it). Lesson for future dispatches: after editing a master,
  you cannot fake a warm pre-fix interface; a genuine before/after for
  importers must be measured before the edit. The run that revealed this
  also produced the valid HF-after row.
- Prose: the module claimed `γ-compute` was the tower's *only* unfolding;
  with `γ-compute-full` added that is no longer true, so the sentence was
  corrected in both languages (English `:659`, Chinese `:675`) to say
  `γ-compute` is its unfolding with its endpoint restated to the closed form
  `+ω (U α)`. This is the one prose change beyond the measured snippet.
- Saved interfaces under `/tmp/t87/` (`Bridge.agdai.before` (00:11),
  `Bridge.agdai.prefix` (pre-fix regen), `Bridge.agdai.postfix`, `HF.agdai.pre-run`)
  are regenerable cache artifacts; the live cache is in the clean post-fix
  state (`Bridge.agdai` and `HF.agdai` regenerated, matching current sources).
