## 1. The D-10 gate

### 1.1 The exact inequality, stated

Write `off(x, δ)` for the least `n` with `x ∈ Sset (sucIter n δ)` — the **tower offset** of `x`
above the index `δ`. The brief's target, spelled at the object it is about, is

> **(T)** `C ∈ Sset δ` ⟹ `codeSet C k ∈ Sset (+ω δ)`.

The brief proposes to reach (T) from a *per-code* fact ("each single code at a finite offset above
the carrier's stage") by the claim that *"the +ω block absorbs the unbounded-but-finite numeral
ranks"*.

**That inference is invalid, and the gate's job is to say so before 1,400 lines are spent on it.**

### 1.2 The refutation, mechanized

`Sset` is transitive at every index (`Hierarchy:285`, `Sset-trans`), membership in any level
factors through one stage strictly below (`Hierarchy:320`, `Sset-out`), and a member of `+ω δ`
lies in one finite iterate (`OrdBlocks:107`, `+ω-out`). Chaining those three:

```agda
blockFactor : (δ x : S) → ⟨ x ∈ˢ Sset (+ω δ) ⟩
            → ∥ Σ[ n ∈ ℕ ] ⟨ x ∈ˢ Sset (sucIter (suc n) δ) ⟩ ∥₁

blockBound  : (δ x : S) → ⟨ x ∈ˢ Sset (+ω δ) ⟩
            → ∥ Σ[ n ∈ ℕ ]
                ((y : S) → ⟨ y ∈ˢ x ⟩ → ⟨ y ∈ˢ Sset (sucIter (suc n) δ) ⟩) ∥₁

codeBound   : (C δ : S) (k : ℕ) → ⟨ Codes.codeSet C k ∈ˢ Sset (+ω δ) ⟩
            → ∥ Σ[ n ∈ ℕ ] ((φ : Formula ⟪ C ⟫ k)
                → ⟨ Codes.code C φ ∈ˢ Sset (sucIter (suc n) δ) ⟩) ∥₁
```

**The verified rank inequality, in one line:**

> `codeSet C k ∈ Sset (+ω δ)` **⟹** `∃ n. ∀ φ. off(code φ, δ) ≤ n`.
>
> The ω-block membership of the code set is a **uniform** bound on every code's offset. Block
> membership absorbs nothing that plain containment did not already absorb; what `+ω` buys for `⊆`
> it cannot buy for `∈`, because the level it lands in is transitive.

Nothing in `blockFactor`/`blockBound` mentions the shape of a code, so the statement holds for
**any** coding whatever. `codeBound` is the same fact read at the code set through
`code∈codeSet`, and `code∈codeSet` is the one property every candidate coding must have. **The
flat re-coding is refuted at the gate, not at the build.**

This is exactly the shape of K2's own refutation (`k2-report.md:61-71`: transitivity plus
unbounded depth kills every finite offset), re-run one block up. K4 had already written the
argument in prose (`k4-report.md:96-104`, finding (b)) and then, in its lesson 2
(`k4-report.md:325-331`), attributed the cofinality to the *encoding* and licensed the re-coding.
**Lesson 2's diagnosis is what this gate overturns**: the cofinality of the codes is a fact about
the encoding, but the obstruction to (T) is a fact about the **tower's successor step**, and no
encoding touches it.

### 1.4 The offsets, measured — what the flat coding would actually have bought

Against `Sset-suc : Sset (sucV β) ≡ step (Sset β)` (`Hierarchy:410`) and `step-in-img`
(`Step:403`), one application of one of the sixteen operations costs exactly **one** offset. For
`δ ≥ ω` the positions and tags are numerals and the labels are members of `C`, so all leaves sit
at offset 0 (`Sset-trans`, `numeral∈J`). Then:

| coding | code of `φ` | offset above `δ` |
|---|---|---|
| delivered, nested | `mkTag t (pr … …)`, two `pr` layers per node | `2·depth(φ) + O(1)` |
| briefed, flat | `{ pr (# i) lᵢ : i < m }`, `m` = number of nodes of `φ` | `1 + 2⌈log₂ m⌉` |
| **required by (T)** | — | **`O(1)`** |

The flat coding is a genuine and large improvement: it takes the per-code offset from **linear in
depth** to **logarithmic in size** (for `¬̇ⁿ ⊤̇`: `2n + O(1)` down to `2⌈log₂(n+1)⌉ + 1`). It is
still divergent, and (T) needs a constant. The assembly is where the offset lives, not the pair
nesting: `pr (# i) lᵢ` is one step, and merging `m` of them into one set is `⌈log₂ m⌉` rounds of
`F0` then `F5`, two steps each. No amount of flattening removes the `log`.

**Why `O(1)` is not reachable by this family at all.** `Sset` at a successor is a **single**
application of the basis (`Sset-suc`), not the rud closure — the closure is reached only at the
top of the block. So `Sset (sucIter n δ)` contains exactly the operation-terms of depth `≤ n` over
`Sset δ ∪ {Sset δ}`, and a family of codes at a fixed offset would have to be a family of
fixed-depth terms. The only way an infinite family of *finite* codes sits at a fixed depth is if
the codes are already **members of `Sset δ`** (offset 0), which is precisely the case where
`Sset δ` is rud-closed — i.e. **`δ` a limit**. That case is §3.

## 2. The literature check

Delegated (per the standing dossier rule) against the in-repo corpus `_build/literature/` —
Devlin *Constructibility*, Jensen's fine-structure book, Jech, and Schindler–Zeman. The question
asked was whether the **membership** form `Def(U) ∈ rud(U ∪ {U})` — which is `BlockPow` verbatim —
is a theorem anywhere.

**It is not.** The dossier's findings, with citations:

1. All four texts state only the **containment/equality** form, and state it for arbitrary
   transitive `U`: Jensen Cor. 2.2.14 (`jensen-book_sec_2_2.txt:295`), Devlin VI.1.17
   (`dev6.txt:1154-1157`), Jech Cor. 13.8 (`jech13.txt:288-290`), SZ Lemma 1.4
   (`sz-full.txt:161-163`). Zero occurrences of `Def(U) ∈ …` anywhere.
2. The only text that gets an L-level into the J-hierarchy **as a member** is Devlin VI.2.3
   (`dev6.txt:1583`, proof at `:1628-1652`), and its shape is
   > `u ∈ M`, `M` **rud-closed and amenable** with `Fml₀ ⊆ M` ⟹ `Def(u) ∈ Def(M) ⊆ rud(M ∪ {M})`.

   In this development's indexing that reads: **`Lset ζ ∈ Sset δ` with `δ` a LIMIT ⟹
   `𝒟ₒ (Lset ζ) ∈ Sset (+ω δ)`**. That is `BlockPow` **plus `⟨ isLimit δ ⟩`**, and nothing weaker
   is proved anywhere.
3. Jensen explicitly declines to prove the L-to-J relationship at all
   (`jensen-book_sec_2_3.txt:39-47`).
4. Nobody claims a fixed finite stage. `rud(U) = ⋃ₙ sⁿ(U)` is stated as an ω-union in every text
   (`jensen-book_sec_2_3.txt:76`, `:129`; `dev6.txt:1565`), and Jech is explicit that the number
   of Gödel-operation steps **grows with `φ`** (`jech13.txt:279-281`). The one fixed-finite-stage
   statement in the corpus runs the other way (Devlin VI.2.4, `dev6.txt:1704-1713`: one `S` step
   costs five `L` steps).
5. Internal satisfaction exists only in **finite truncations** as members (SZ Prop. 1.12,
   `sz-full.txt:430-457`); the full relation is `Δ₁^M`, never a member (SZ 1.13/1.14, Jensen
   2.2.17, Devlin VI.1.14).
6. On the brief's named mine specifically: Jensen puts the codes in `H_ω`
   (`jensen-book_sec_2_2.txt:596-602`) and carries **parameters in a separate evaluation function**
   (`:584-585`); SZ likewise (`sz-full.txt:461-480`). Devlin's Ch. II language `ℒ_u` carries a
   constant per `x ∈ u`, so his quantifier bound `K(u)` **depends on `u`** (`dev2.txt:602-609`) —
   which is the delivered `Formula ⟪C⟫ k` shape, and it is the reason the code here cannot be a
   pure `H_ω` object with the parameters travelling separately.
7. Devlin II.1I(viii) (`dev2.txt:2334-2346`) asks the reader to show `f(u) = Def(u)` is
   **primitive recursive** — explicitly *not* rud (the p.r. schemas add the recursion schema that
   rud omits, `dev2.txt:2194-2218`, `jensen-book_sec_2_2.txt:5-7`). That is the literature's own
   placement of `Def` as an operation, and it is one class above rud.

So `BlockPow` as recorded in `SatTable:349-351` is **stronger than anything in the literature**,
and the gap is exactly the limit hypothesis on `δ`.

## 4. Where the route's real gap now sits

`BlockPowLim` does **not** give `GeneralPow` by the delivered `block→general`
(`SatTable:378-393`), which takes its `δ` from `Sstage γ limγ (Lset ζ) L∈` — an arbitrary member
stage, not a limit. Feeding a limit instead requires **a limit `δ ∈ γ` holding `Lset ζ`**, and
that is refuted at `γ = +ω δ₀` with `δ₀` the (successor) entry stage: k4's concrete instance
`γ = ω·2`, `ζ = ω+3` (`k4-report.md:87-93`). Passing to `δ' := +ω δ` instead only works when
`+ω δ ∈ γ` strictly, and `+ω-fits` (`SatTable:353`) permits `+ω δ ≡ γ`, which is exactly the bad
case.

And the consumer cannot be asked for a bigger `γ`. I checked it directly: `Reduce`'s induction
carries `p2 : (γ : S) → ⟨ isLimit γ ⟩ → ⟨ β ∈ˢ γ ⟩ → ⟨ Lset β ∈ˢ Sset γ ⟩` (`Bridge:742-751`),
so `γ` is universally quantified **inside the induction hypothesis**; `defStage∈J` is called at
whatever `γ` the caller supplies. k4 §1.3(c)'s "zero slack" is confirmed at the source.

**So the residue moves from the coding chapters to the routing.** The open question is no longer
"which coding", it is:

> Can `GeneralPow` be derived from `BlockPowLim` — i.e. can the `γ = +ω δ₀`, `δ₀` a successor case
> be closed, or must `Reduce`'s induction statement be reshaped so that the level it demands is
> always one with a limit stage below it holding the carrier?

That is a `Bridge`/`DefInJ`-side question, and it is an architecture fork, not a batch. I am
surfacing it rather than picking, per the boundary rule.

## 8. Lesson candidates (IDs for the owner)

1. **D-series, new: a level's transitivity converts every "the block absorbs it" claim into a
   uniform-bound claim.** Rule: in a cumulative tower whose levels are transitive, `x ∈ Level(α)`
   for a limit `α` is never weaker than `∃ β < α. x ⊆ Level(β)`. So a plan of the form "the
   members are at unbounded-but-finite offsets, and the limit/block absorbs that" is **always**
   false for membership and **always** true for containment, and the two must be separated before
   any coding is designed. Measured here: the claim was refuted through three chained delivered
   lemmas (`Sset-out`, `+ω-out`, `Sset-in`/`Sset-trans`), 16 lines, before any chapter was opened;
   the build it removed was priced at 1,400 lines. Sibling of D-10 and the general form of K2's
   own cofinality finding.
2. **D-10 sub-rule: when a residue's TARGET is stronger than the literature's theorem, the batch
   that "repairs" it is repairing the wrong object.** K4 correctly found that the delivered
   supplier's index was unavailable, and correctly recorded `BlockPow` as the index-free residue.
   What was not checked is whether `BlockPow` is a theorem *anybody has*. It is not: the corpus in
   `_build/literature/` proves `Def(u) ∈ rud(M)` for a **rud-closed** `M ∋ u`, one hypothesis
   stronger, and states the rud closure as an essential ω-union everywhere. Cost of not checking:
   one dispatched batch. **The check is a twenty-minute delegated dossier against the in-repo
   corpus, and it should be mandatory for any residue stated as a named classical lemma.**
3. **A "fact about the encoding" and a "fact about the tower" can wear the same clothes.** K4's
   lesson 2 said: when a cofinality is recorded as a fact about the target, check whether the
   ranks come from the mathematics or the representation. Correct, and it licensed the re-coding.
   The missing half: **also check whether the obstruction the cofinality was blamed for is a fact
   about the tower's own step.** Here the codes' cofinality *is* representational (and the flat
   coding really does cut it from linear to logarithmic), but the obstruction to the target is
   `Sset`'s single-application successor, which no representation touches. Both halves of the
   check are cheap; only one was run.
4. **Measure the improvement even when you reject the plan.** The flat coding was not built, but
   its offset was computed against the delivered `step` arithmetic: `2·depth` → `2⌈log₂ size⌉`.
   That number is what makes "refuted" defensible rather than merely asserted, and it is the
   number a future batch will want if `O(log)` ever becomes sufficient. A D-10 stop that reports
   only "false" throws this away.
5. **The positive half of a D-10 stop is worth more than the negative half.** Two of the five
   theorems here (`codeSet-in-block`, `blockPow-at-limit`) took eight lines, needed nothing new,
   and moved the campaign's residue from a two-limit telescope with a refuted index to a
   one-hypothesis statement with a satisfiable one. A stop report should always try to instantiate
   the delivered machinery at the corrected index before concluding that the delivered machinery
   is the problem.
6. **C-8 extension: `_build` report filenames collide across goal codes.** `_build/p1-report.md`
   was already the [L3.30-P1] report and is the cited provenance for I-2, D-7 and C-11; the brief
   directed this batch to write to that exact path. A brief-directed overwrite is a blind spot no
   linter covers. Rule: `_build` reports carry the goal code
   (`_build/l3.31-p1-report.md`), and a batch that finds its report path occupied writes beside it
   and says so.
