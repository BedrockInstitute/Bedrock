## 1. What is this project building, and how?

Bedrock is a machine-checked formalization of set theory in Cubical Agda. The
one-line framing is "Laying the groundwork for the metaphysics of V"
(`README.md:15`): a machine-checked development of the set theory underlying
contemporary questions about the universe of sets, namely forcing, inner
models, and the structure of V (`README.md:17-19`). The immediate, self-
contained first goal is a full mechanization of

> `L` ⊨ GCH, where `L` is the constructible hierarchy built over the cumulative
> hierarchy `V` realised as a higher inductive type (`README.md:23-27`).

The construction registry states the endpoint more precisely: `L ⊨ ZFC ∧
L ⊨ GCH`, stated on the "Def tower" (`isL`), with the AC-only trophy as a
waypoint (`dev/PLAN.md:36-38`). The current milestone in the registry title is
porting `L ⊨ ZFC` from the source repository `choukh/fol-reification`
(`dev/README.md:10-11`, `dev/PLAN.md:23-28`).

How it is built:

- One literate `.lagda.md` "master" per module holds the Agda code exactly once
  plus English/Chinese/Japanese prose wrapped in `<!--en--> / <!--zh--> /
  <!--ja--> / <!--/-->` markers (`dev/STYLE-i18n.md:6-11`). Agda reads only the
  ` ```agda ` fences, so code cannot drift between languages
  (`dev/STYLE-i18n.md:6-11`; `src/README.md:3-13`).
- `src/Everything.lagda.md` is the aggregator and the book's reading catalog;
  it imports every module, so `agda src/Everything.lagda.md` typechecks the
  whole development, and `make check` runs exactly that (`src/README.md:15-23`;
  `Makefile:36,48-49`). It currently has 123 import/`open import` lines (my
  count, `src/Everything.lagda.md`).
- From the masters, scripts weave per-language mono-lingual copies and render a
  hyperlinked trilingual site, all generated into `_build/` and never committed
  (`scripts/README.md:12-25`).
- The design doctrine is "host-language maximalism": rather than transcribing
  the textbook ZF axioms, every notion is reconstructed in type-theory-native
  idiom, with the deep-embedded `Formula` as the object studied
  (`README.md:53-59`).
- The tree is `--safe` and postulate-free; LEM is a module parameter, not a
  postulate (`dev/PLAN.md:58-59`; D2, `dev/PLAN.md:167`).

Confidence and what I inferred rather than read: high on the endpoint and the
architecture (both read directly: `README.md:23-27`, `dev/PLAN.md:36-49`).
Medium on the shape of the codebase: I inferred the module organization from

## 2. How is the work actually run?

There are three roles, clearly separated in the documents:

- The **owner** rules. Ratified decisions are rows in `dev/PLAN.md` section 3
  (`AGENTS.md:72`); the owner also rules on terminology dossiers
  (`dev/ORCHESTRATION.md:283-298`) and approves pushes
  (`dev/ORCHESTRATION.md:280-281`).
- The **orchestrator** writes briefs, audits returns, wires
  `src/Everything.lagda.md`, updates the ledger, commits, and never pushes
  (`dev/ORCHESTRATION.md:276-281`; `AGENTS.md:102-106`).
- **Dispatched agents** (me, in this case) work against a pinned brief and
  never commit or push (`AGENTS.md:105-106`; `dev/ORCHESTRATION.md:276-281`).
  Codex is the default tier for every dispatch; an Opus subagent is used only
  when the owner says so for that task or the orchestrator judges the task
  very-very-heavy (`dev/ORCHESTRATION.md:13-26`).

How a change gets made:

1. A task is registered in `dev/PLAN.md`'s task index **before** the work
   starts, never backfilled (`dev/PLAN.md:223-225`, rule 6;
   `dev/ORCHESTRATION.md:179-183`). The task index has one row per code, capped
   at 200 characters, enforced by `scripts/check-task-index.py`
   (`dev/PLAN.md:238-243`).
2. The brief is pinned in `_build/briefs/` before dispatch, carrying tier,
   goal, CWD, write scope, read scope in order, constraints, and return
   (`dev/ORCHESTRATION.md:45-59`). My own brief is pinned at
   `_build/briefs/l3.32-t120-brief.md:1-5`.
3. The rule bundle is pasted into the brief mechanically; the kind is DERIVED
   from the write scope, never self-declared, and the dispatch path refuses a
   brief that does not carry it (`dev/ORCHESTRATION.md:85-95`;
   `dev/rules.toml:34-35`; `scripts/rules.py:69-77`). For my report-only write
   scope the derived kind is `recon` and the bundle is D-10, C-22, P-l
   (`dev/rules.toml:47-49`).
4. Work runs under concurrency and heap ceilings: four agents at `-M8g`, two at
   `-M12g`, one Agda process per agent (`dev/ORCHESTRATION.md:28-39`);
   dispatched agents run `GHCRTS=-M8g agda <file>` (`AGENTS.md:107-109`).
5. On return, the orchestrator reads the report, verifies independently (re-
   running the typecheck, spot-checking `file:line` claims, grepping absence
   claims), fills free slots, wires `src/Everything.lagda.md`, gates with
   `make check`, commits with the goal code, records the ruling in PLAN and the
   episode in JOURNAL, brings the ledger current, dispatches a terminology
   dossier if a load-bearing term was introduced, and refreshes the dashboard
   (`dev/ORCHESTRATION.md:212-273`).
6. The gate: `make check` typechecks the masters and runs every checker
   (prose, markers, Agda style, rule IDs, glossary, ledger, probes, tree
   invariants, REUSE), `AGENTS.md:36-41`; it is launched in the background
   because a cold typecheck takes about twelve minutes, and full gates are
   batched (D28, `scripts/README.md:183-186`). A pre-commit hook runs the fast
   checks on staged files (`scripts/README.md:260-268`).
7. CI re-runs `make check` on every push (`typecheck.yml`), and merge to `main`
   deploys automatically to Cloudflare Pages (primary) and GitHub Pages
   (mirror), with credentials as org secrets that contributors never handle
   (`.github/workflows/README.md:6-15`; `AGENTS.md:82`).

Human contributors are pointed at `CONTRIBUTING.md`, which tells them to open
the repo in an AI agent, let the agent enforce the rules, and let `make check`
plus CI be the machine backstop (`CONTRIBUTING.md:6-15`); AI agents work from
`AGENTS.md` (`README.md:108-109`).

## 3. What rules and disciplines bind you, and where did they come from?

The bundle that binds THIS task is the recon bundle: D-10, C-22, P-l, emitted
by `scripts/rules.py --for recon` (`dev/rules.toml:47-49`). Their content:

- **D-10. Price the truth of a recorded residue before pricing its proof.**
  A recorded residue names a target, and a target can be false; check the
  target's truth at the intended generality before dispatching a discharge
  batch, and record any correction beside the original
  (`dev/LESSONS.md:1271-1277`). The WHY is measured: the r3c report's third
  residue was false two limits up, and the r2c chain showed the mirror case
  (`dev/LESSONS.md:1278-1281`).
- **C-22. A dispatched agent writes its deliverable incrementally, never at
  the end.** A partial dossier is a real deliverable; an unwritten perfect one
  is not (`dev/LESSONS.md:1940-1944`). The WHY is measured: a literature-fetch
  agent located everything correctly and died before writing a line
  (`dev/LESSONS.md:1945-1948`). I am obeying it by writing this report first
  and filling it.
- **P-l. A statement may be ABOUT a concrete stage without dragging that
  stage's PRESENTATION into its type.** Naming a transparent construction in a
  statement's type re-normalizes it at every check (`dev/LESSONS.md:1965-1973`).
  The WHY is a controlled measurement pair: `L.Rud.HF` at 0.030 s per line with
  sealed stages against `L.Ordinal.SquareLaw` at 3.424 s per obligation with
  transparent `⟪ ⟫` positions, 46x apart in one repository
  (`dev/LESSONS.md:1974-1984`). P-l is also the law behind the current
  check-cost campaign and why I had to read it even though this task writes no
  Agda (`dev/ledger.toml:687-698`, `dev/ledger.toml:650-653`).

Beyond the bundle, `AGENTS.md` binds every agent: write structure-generic
(`AGENTS.md:19-20`), run `make check` before committing (`AGENTS.md:36-41`),
author English first then translate and cross-check the Chinese and Japanese
against each other (`AGENTS.md:22-23`), verify a load-bearing assumption cheaply
before heavy work (`AGENTS.md:23-24`), state size projections in both calibers
(`AGENTS.md:133-136`), never commit generated or probe files (`AGENTS.md:28-
29`), never delete retired code (`AGENTS.md:29`, `AGENTS.md:146-157`), never
use an em dash, never add unpinned dependencies, never add in-file SPDX headers
(`AGENTS.md:30-32`). For dispatched agents specifically: never touch
`src/Everything.lagda.md`, never commit or push, heap cap with one Agda process,
write incrementally, evidence as `file:line`, and a stop is a deliverable
(`AGENTS.md:105-115`). Estimates carry two calibers, naive and calibrated, at
about 1.3x for probe-reachable parts and 3x for survey-only parts
(`AGENTS.md:133-136`, `dev/PLAN.md:256-281`); every block is gated before it is
funded (`AGENTS.md:127-131`); an idle agent slot is a defect
(`AGENTS.md:143-144`).

Where the rules came from, and which explain WHY:
