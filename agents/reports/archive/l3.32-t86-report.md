## 4. The sealing plan

**Top module, measured: L.Rud.Bridge, 933 s in the full run.** A per-definition
profile of Bridge alone (warm deps, own interface moved aside,
`GHCRTS=-M8g agda --profile=definitions src/L/Rud/Bridge.lagda.md`, exit 0,
total 939.2 s) shows 95% of the module's time is its own γ index-tower family,
not consumers:

| definition | time (s) | what it is |
|---|---|---|
| `γ-lim` | 265.4 | every tower value is a limit, `(α : S) → isLimit (γ α)` |
| `ordStep` | 159.6 | the induction step of `γ-ord` (`IsOrd (γ α)`) |
| `γ-mono` | 105.8 | tower monotonicity in the index |
| `γ-compute` | 90.1 | the tower's only unfolding read lemma |
| `sub` / `sup` | 54.9 / 54.2 | the two directions of `γ-suc` |
| `∅∈γ∅` | 54.7 | the base membership at `γ ∅` |
| `Ul∈γl` | 54.2 | `U l ∈ γ l`, the carrier one ω-block below the landing |
| `γ-mem` | 53.4 | `U δ ∈ γ δ` |

Every one of these is a consumer of `γ-compute`, whose stated type ends at the
tower body `γ α ≡ towerStep α (λ δ _ → γ δ)`. Each consumer's `subst` then has
to convert `towerStep α (λ δ _ → γ δ)` to `+ω (U α)`, re-normalizing the
`⋃ (sett ⟪ α ⟫ …)` union tower inside `towerStep`; the same conversion is paid
about eight times, once per definition.

**The measured fix (P-c/R-36 applied one layer up): restate the read lemma to
end where every consumer actually uses it, and absorb the tower normalization
once inside the seal.** In a scratch copy (`/tmp/t86-src/ProbeT86Bridge.lagda.md`,
module renamed to avoid the top-module path clash, body identical), the change
was: keep `γ-compute-full : γ α ≡ towerStep α (λ δ _ → γ δ)` (unchanged body),
add

```agda
opaque
  towerStep≡+ωU : (α : S) → towerStep α (λ δ _ → γ δ) ≡ +ω (U α)
  towerStep≡+ωU α = refl

opaque
  γ-compute : (α : S) → γ α ≡ +ω (U α)
  γ-compute α = γ-compute-full α ∙ towerStep≡+ωU α
```

and change nothing else. All ten uses of `γ-compute` are subst applications
whose endpoints match the new type exactly (`src/L/Rud/Bridge.lagda.md:728`,
`:743`, `:781`, `:783`, `:854`, `:856`, `:891`, `:969`, `:1108`), so no
consumer edit was needed. **Measured: Bridge's own check falls from 939 s to
170 s (profile Total, warm deps, one process, `GHCRTS=-M8g`, exit 0).** Saving:
769 s = 12.8 minutes per full cold check, for +6 lines and zero consumer
risk (all exported facts keep their types; only the internal read lemma's
statement changed). The one external consumer of `γ-compute` is `L.Rud.HF`
(`src/L/Rud/HF.lagda.md:46`, use at `:616`); a faithful probe copy of HF
importing the sealed module checks green in 5.7 s
(`/tmp/t86-src/ProbeT86HF.lagda.md`, exit 0), confirming the changed type is
compatible. The sealed run wrote its interface next to the scratch source
(`/tmp/t86-src/ProbeT86Bridge.agdai`); the tree's `Bridge.agdai` was moved
aside for the experiment and restored after; no `src/` master was modified.

## 5. Is five minutes reachable?

**No. Five minutes is not reachable by sealing, and the measured floor is
roughly 12 minutes of profile-instrumented check time, with the honest
un-instrumented wall somewhat below that but nowhere near five.** The
arithmetic, all measured numbers:

| step | profile time left |
|---|---|
| full cold check today (measured: 2,501 + 222 recovered) | 2,723 s |
| Bridge read-lemma fix (measured: 939 to 170 s) | 1,954 s |
| D18 retirement of the internalization tree (measured subtree sum) | 1,598 s |
| SquareLaw, if it responds like Bridge (unmeasured, optimistic) | about 912 s |
| Condensation, if it responds like Bridge (unmeasured, optimistic) | about 746 s |

Even with every optimistic lever applied, the residual is about 750 s, and
that floor is not Bridge, SquareLaw or Condensation: it is the ordinary tail
(everything except the three hot modules and the retiring tree, measured sum
about 375 s) plus the three hot modules' residuals after their fixes (about
377 s). No sealing lever applies to the ordinary tail: those modules are
cheap per line (0.01-0.10 s/line) and are the sealed discipline's own
product. Five minutes would require the ordinary tail to check in under a
minute combined, which no measured datum supports.

**What is reachable, honestly:** with the measured Bridge fix alone, the full
cold check falls from 45:23 to about 32:30 profile; the wall-clock analogues
are uncertain because the 27:54 record and the profiled run differ in
instrumentation and load: anchored on 27:54 minus the measured 12.8-minute
Bridge saving, the Bridge-fixed check is about 15 minutes wall; anchored on
the measured profile-to-wall ratio (about 0.6-0.7), it is about 20-22 minutes;
the honest band is 15-22 minutes. Adding the already-booked D18 retirement of
the internalization tree (measured subtree sum, 5.9 profile-minutes) brings
the profile total to about 26:38, roughly 11-18 minutes wall. If SquareLaw's
pair-injectivity deduplication succeeds (a build, not a seal), the profile
total approaches about 15:12, roughly 7-12 minutes wall; Condensation would
need its own fix on top (about 6-10 minutes wall for all three). The residual
is made of the concrete-pairing injectivity walls (SquareLaw's four proofs),
the γ-tower read path (fixed by the Bridge restatement), Condensation and the
ordinary per-module cost of the surviving trunk, in that order.

The owner's target line, stated plainly: **sealing gets the check from about
28-45 minutes to about 15-22 minutes wall (Bridge), and the already-planned
retirement gets it to about 11-18 minutes; five minutes needs the SquareLaw
pair-injectivity work AND a Condensation fix to land AND the surviving tail to
compress about 4x beyond anything measured, so the honest reachable figure is
roughly 7-12 minutes wall, and five minutes is not funded by any measured
lever.**
