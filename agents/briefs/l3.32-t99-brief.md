## THE ONE QUESTION

`SquareLaw`'s counting chase is stated at the concrete presentation `⟪ # n ⟫`.
**Can the same chase be stated against an abstract finite-enumeration
interface, and does it elaborate inside the 8 GB heap cap?**

## WHY THIS EXACT PROBE, AND WHY IT IS NOT A REPEAT OF [T88]

`[T88]` probes 2 and 2a already tried a generic restatement and **heap
exhausted at `-M8g` twice**: 10:26 with instantiations, 26:10 with the generic
module alone (`_build/l3.32-t88-report.md` section 4b, logs
`/tmp/t88-squarelaw-probe2.log`, `/tmp/t88-squarelaw-probe2a.log`).

**Read that section before you build anything.** Its abstraction was
`NoInj (A : Type ℓ) (into : (m : ℕ) → ⟪ # m ⟫ → A) (into-inj : ...)`, which
abstracts the TARGET while **leaving `⟪ # m ⟫` in the telescope**. So the
presentation was still there, and by `[T98]`'s root cause that is exactly the
thing that costs.

**This probe abstracts the SOURCE instead**, which is the untried direction:

```
module _ (E : ℕ → Type ℓ)
         (toFinE   : (n : ℕ) → E n → Fin n)
         (toFinE-inj : ...)
         (fromFinE : (n : ℕ) → Fin n → E n)
         (fromFinE-inj : ...)
         where
```

with the current `no-inj-finite` chase body using `E` for `⟪ #_⟫`, and **no
`⟪ # m ⟫` anywhere in the telescope**, then instantiated at `E n := ⟪ # n ⟫`
with the delivered count from `FiniteBase`.

**If `[T88]`'s wall was the presentation in the telescope, this clears it. If
it walls anyway, the chase's content is presentation-bound and the answer is
settled the other way.** Either way the question dies today.
