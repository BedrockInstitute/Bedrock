## 2. Method

The design's day 1 row specifies the probe (`dev/memos/L9-pod-program-design.md:3254`): a
scratch worktree, one cold build, then one comment-character change in each of five
masters, one per depth class, timing `agda src/Everything.lagda.md` after each.

**The worktree.** `git worktree add /tmp/l9-b3-probe HEAD` at `f1d4492`. The worktree
carries no `_build`, so the first build is cold by construction. The live tree is never
touched.

**The command is the POD's, not this probe's.** `run_agda()` pins the caliber at
`dev/memos/L9-pod-program-design.md:489`:

```
CAP  = "-A64m -I0 -M8g"          # R13, AMENDED BY A14 and A15. One caliber PER
                                 # TIER: WIDE is -M8g at four concurrent, HEAVY
                                 # is -M12g at two. A15: a per-task acceptance
                                 # run uses this; a whole-tree make check uses
                                 # -M16g, C-12's orchestrator caliber.
```

**Amendment A15 rules the caliber this probe needs**
(`dev/memos/L9-pod-program-design.md:111-115`): a per-task acceptance run uses `-M8g`. So
this probe measures the ruled caliber and not a neighbouring one. The distinction is
expensive. `scripts/measure/check-timing.py:255-258` measured the two GC flags at 22.3
percent, 163.49 s against 133.69 s on one tree, so a price taken at a bare `-M8g` would
read high by up to a fifth. `make typecheck` at `Makefile:48-49` runs neither form: it omits
`--safe` and exports `-M16g`.

`src/Everything.lagda.md:27` declares `--safe`, so `run_agda()` adds the flag. The probe
runs `agda --safe src/Everything.lagda.md` with `GHCRTS="-A64m -I0 -M8g"`, one process at
a time, and it refuses to start when Agda already runs.

**Why the comment character.** Agda reads the fenced code of a `.lagda.md` master and never
the prose. A change to one prose character changes the source hash and nothing else. The
recompile it forces is therefore pure dependency cost, with no new elaboration work. The
probe toggles the case of one ASCII letter in the last plain prose line. It skips every
`<!--en-->` marker line, it moves no line, and it changes no in-fence line count.

**The order.** Cold build, warm run with no edit, then the five masters from the shallowest
depth class to the deepest, then a second warm run with no edit. Every run finishes before
the next starts, so every recompile begins from a fully warm tree. The two warm runs bracket
the whole session, so machine drift is visible and not hidden.

### 4.3 The depth model is verified, not assumed

Agda prints one `Checking <module>` line per module it re-checks. Counting those lines in
each run file gives the set Agda actually re-checked. **It equals the reverse closure in
every one of the five classes, and the warm run re-checks nothing.**

| Class | Reverse closure, tracked caliber | `Checking` lines in the run file |
|---|---:|---:|
| Warm, no edit | 0 | 0 |
| d1-leaf | 2 | 2 |
| d2-shallow | 7 | 7 |
| d3-mid | 24 | 24 |
| d4-deep | 45 | 45 |
| d5-base | 99 | 99 |

The tracked caliber counts `src/Everything.lagda.md` and `src/Landmarks.lagda.md`, which the
countable caliber of section 3 drops. `grep -c "Checking " runs/<class>.out` reproduces every
right-hand figure. So the reverse import closure is not a model of the recompile set. It IS
the recompile set, and the POD may price a task from it with no further evidence.

**The seconds are a ONE-SLOT price, and A14 admits four.** This probe ran one Agda process
at a time, and every run file records 0 or 1 in `agda slots before`. Four concurrent writers
share 16 cores, so a WIDE-tier acceptance test will read higher than the table above.
This probe does not measure by how much. `run_agda()` records `concurrency` for exactly this
reason, so the POD's own corpus will answer it after the first WIDE week.

### 5.4 Whether the 34-fold band is closed

**CLOSED. The band was 34-fold because it mixed three different quantities.** The measured
recompile rate spans 1.48-fold across the whole depth range, from a single leaf file to the
whole 97-master tree.

**The top of the band does not price the live tree at all.** `content_rate_measured` is
0.297 and its provenance at `dev/ledger.toml:1940-1963` names the rud witness layer: 589
lines, the pair-family decode, the rename decode and the clause bundle. **Measured today:
`git ls-files src/ | grep -i rud` returns nothing, and 84 archived paths carry the name.**
That module family is retired to `archive/`, outside every gate. A rate measured on code the
tree no longer holds cannot bound a recompile of the code it does hold.

**The middle of the band is a per-module figure read with the wrong denominator.** 0.0257 is
`L.Ordinal.SquareLaw`'s cold seconds over its OWN lines (`dev/ledger.toml:1920`). This probe
recompiled that master and its five consumers together in 23.92 s, against the 23.3 s the
cold profile records for the master alone. The two agree inside the load noise. So 0.0257
bounds one expensive module from above, and this probe measures it at no more than 0.0267 s
per own line. It was never a rate for a closure, and the acceptance test always recompiles a
closure, which averages over the tree.

**What is NOT closed, and it is not a band.** This probe prices RECOMPILE, because a comment
character adds no content. A task that lands NEW lines pays for those lines at its own
family's first-elaboration rate, which this probe did not measure and which the 0.297 figure
shows can be far above the tree average. That term scales with the lines a task WRITES, not
with the tree, and section 5.4's price table does not carry it either. **Name it in the next
estimate rather than folding it into the recompile rate.**

## 8. What this probe did not do

- It measured at concurrency 1. Amendment A14 admits four concurrent Agda writers in the
  WIDE tier, so a WIDE acceptance test will read higher than every figure here.
- It did not measure the first-elaboration cost of NEW lines. That term is separate from the
  recompile rate and it is the one still unpriced.
- It measured one machine, on one day, at a load average of 3.88 to 7.16. The ledger's own
  warning applies (`dev/ledger.toml:2657-2663`): re-measure on a quiet machine.
- It changed the working tree of `/tmp/l9-b3-probe` only, and the worktree is removed. The
  live tree was never touched, and this task committed nothing.
- It did not register `[L9.0]` in `dev/PLAN.md` section 11. The orchestrator owns that file.
- It did not run the other two day 1 probes: gap m1's seed probe and the cold witness price.
