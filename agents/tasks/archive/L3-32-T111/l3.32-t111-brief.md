## WHAT TO BUILD

### 1. The rule amendment

Amend section 6.0 so a dispatched task earns a code, and add whatever rule is
needed to keep the table readable. **At minimum the owner's two requirements
must become rules with enforcement points:**

- a dispatched sub-agent task gets an extended code under its parent goal,
  form `L<goal>.<subgoal>-T<n>`;
- **each code occupies exactly one row**, and that row stays short.

**"Stays short" needs a number and the number needs an argument.** The failure
being prevented is a cell reaching 12,633 tokens. Pick a cap, justify it from
what a useful one-line index entry actually needs, and make it checkable.

Keep the existing rules intact: codes are immutable and append-only, never
reused or renumbered (rule 3), and registration is never backfilled (rule 6).
**Note the tension and resolve it explicitly**: rule 6 says register before
starting, and 110 tasks are already done. Say how the backfill is legitimate
here (it is a one-time reconciliation of existing history, not a new habit) and
make sure the rule you write forbids it happening again.

### 2. The index

A table in `dev/PLAN.md` section 11, **one row per task code**, covering all
110. Each row should carry at least: the code, a short title, the verdict in a
few words (GREEN, RED, REFUTED, DELIVERED, STOPPED, and so on), and where the
detail lives.

**The eight briefs without a parseable title, and any task with no brief at
