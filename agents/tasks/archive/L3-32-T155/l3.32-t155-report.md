## 1. The measurement

The shared part holds 31 masters and 9,203 lines. The source is `.venv/bin/python scripts/ledger.py --trophy-files`. I extracted 597 top-level definitions from the code fences. A definition's span runs from its start to the next top-level name. Line counts use the ledger caliber: non-blank fence lines, comments included.

I classified each definition by its consumers across the surviving tree. I scanned code fences with word boundaries. I handled re-exports in four steps:

1. I parsed every import statement with its using, hiding and renaming clauses.
2. I resolved module aliases to their source masters.
3. I followed public re-exports through the alias chain. Example: `L.Rud.Step` re-exports `Sset` and `Jset` from `L.Rud.Hierarchy` through `ConcreteS` (`src/L/Rud/Step.lagda.md:937`). The AC-side `L.Rud.Bridge` consumes them through `Step` (`src/L/Rud/Bridge.lagda.md:52-53`).
4. I attributed each match to the definition whose span contains it.

The classification is a transitive fixed point. A consumer in a gch-only master never blocks. A consumer in an ambiguous master never blocks (brief method step 1). A consumer in a base or ac-only master blocks. A consumer in a shared master blocks only when the consuming definition is not movable.

The conservative count resolves every doubt against moving. It counts code matches in any reachable master, comments and import lines included. The optimistic count resolves doubts for moving. It counts only in-scope code matches, comments and import lines excluded.

## 5. What I could not classify, and why (D-10)

**Name collisions inside importing masters.** Example: `ModelL` and `AbsL` are module aliases in several masters. A match in a master with its own alias is not a consumer of the audited alias. The scope analysis cannot always tell them apart. The optimistic count may over-attribute. The conservative count over-blocks. Both directions are named doubts.

**Record projections and constructors.** I added field and constructor names to a unit's nameset. Some member extraction picks up helper names inside data spans. One example is `isLevel` in `L/Rud/Hierarchy`. Extra names only add consumer edges. They can depress the movable counts, never inflate them.

**Re-exports through module parameters.** `open X renaming (...)`, where X is a module parameter, resolves only when the alias source is a surviving master. Nested-module re-exports through non-surviving sources are skipped. I found no shared unit name flowing through such a path. I cannot prove the scan complete.

**Where-clause shadowing.** A local helper may reuse a top-level name. A match inside the helper's span then counts as a consumer of the top-level name. This is conservative-safe.

**The Order seed's cone boundary.** I seeded exactly the three names in the ledger record: `Sset-order`, `Jset-order`, `Sset-choice`. `Jset-choice` (`Order:1059`) is not seeded. It is a one-line corollary of `Sset-choice`. The wing or the bridge may need it. Classify it as borderline.

**Overhead lines.** Imports, options and module headers are not definition lines. They stay with the master. The movable totals do not include them.

**Prose.** I excluded prose from both headline counts. Prose cannot create an Agda dependency. The brief's literal `rg -w` method includes it. The literal bound, with transitivity and every doubt against moving, is 2,310 lines. The difference is prose noise, mostly in `src/Everything.lagda.md`'s reading catalog.

## 6. What contradicts this brief

The brief's literal `rg -w` method misses two consumer classes. It misses same-master transitive consumers. A definition used only inside a shared master by an AC-required definition stays. It misses re-exported names behind aliases. `Step` re-exports `Sset` and `Jset` from `Hierarchy` through `ConcreteS`. Both classes are real. I used a name-flow scan with same-master transitivity. My reading wins.

The consumer test alone marks Order's suppliers movable. D33 declares them AC-route content. The seed is the route-honest reading. Both readings are in section 7.

Movable does not always mean saved. Under the current file-granular rule, a moved definition saves AC lines only when its sibling lands in the gch closure. The ambiguous content has no surviving gch consumer. Its siblings would land ambiguous and still bill AC. A companion ruling, or the wing's builds, converts those lines into savings. This report proposes. The orchestrator applies.
