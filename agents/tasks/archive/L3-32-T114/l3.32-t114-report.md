## 2. The mermaid decision

I emit the flowchart as its **labelled mermaid source in a `<pre>` block**,
not as a rendered diagram, and I did not vendor a renderer. Why:

- No mermaid renderer exists anywhere in the repository or its local caches
  (checked `node_modules` and the plugin cache; none found), and the page
  must be self-contained with no network, so inlining a renderer would mean
  adding a network dependency to fetch one, which the brief forbids.
- A vendored mermaid bundle is a multi-megabyte JavaScript payload that would
  swamp a self-contained orientation page, and the repository's strict
  licensing setup (`REUSE.toml`) would need a new dependency declared for it.
- The block IS the canonical data (`dev/LEDGER.md:316-344`). Showing it
  verbatim is the honest "generated from canonical data" choice: the source
  cannot drift from what the route section actually says, and the owner can
  paste it into any Mermaid-capable viewer.

The panel labels the block as source, names its file and mtime, and the page
otherwise needs no JavaScript at all.

## 3. The staleness check

`scripts/check-dashboard.py` compares the generated page's mtime against every
source it derives from: `dev/ledger.toml`, `dev/LEDGER.md`, `dev/PLAN.md`,
`scripts/ledger.py`, `scripts/dashboard.py` itself, and the newest
`_build/briefs/*.md` mtime. `_build/dashboard.html` is stale if any source is
newer than it; a missing page is stale by definition. Every panel also prints
its own source and mtime on the page, so staleness is visible to the owner
without running anything.

It is **informational and always exits 0**: `_build/` is git-ignored
(`.gitignore:2`), so a fresh clone has no dashboard, and a gate that failed on
a missing generated file would block every new clone. The orchestrator runs
`make dashboard-stale` after regenerating at a return; the report tells them
what to refresh, and the owner sees the board.

## 5. How to run it

```sh
make dashboard            # writes _build/dashboard.html (self-contained)
make dashboard-stale      # informational staleness report, exits 0
python3 scripts/tests/test_dashboard.py   # regression tests, 27 checks
```

`make dashboard` runs `scripts/dashboard.py --out _build/dashboard.html` with
the venv interpreter and writes one self-contained HTML file (about 52 KB,
inline CSS, no JavaScript, no network references). The generator reads the
canonical sources named in section 1, and it normalizes any banned em dash in
data text to a hyphen so the page obeys the prose rule; a scan of the built
page found zero em dashes and zero network references. If a source is missing
or unparseable, the affected panel says so instead of guessing, and the
generator still exits 0.

Scope discipline: no `dev/*.md`, `dev/ledger.toml`, `src/` or `.claude/` file
was edited; nothing was committed. Changed files are `Makefile` (the
`dashboard` and `dashboard-stale` targets), `scripts/dashboard.py`,
`scripts/check-dashboard.py`, `scripts/tests/test_dashboard.py` (new),
`scripts/README.md` (documentation), and the generated artifacts under
`_build/`.
