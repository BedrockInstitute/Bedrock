# [L3.32-T75] The `sndIn` defect: comment or code?

## Verdict, compressed

**The code is wrong; the comment is right.** The membership conjunct of
`sndIn ku kw` targets the singleton member (`var (suc zero)`, the first
binder's witness), so the formula reads "ku is the FIRST component of the
pair kw" (equivalently "ku equals the element of kw's singleton member"),
not "ku is a member of the SECOND component" as the comment states. All
three use sites (`snd∈Snd` at `:401`, `limIn` at `:510`, `Rg` at `:535`)
require the second-component reading, and the delivered range read that the
structural story is supposed to bound (`LevelFormula`'s `Rg`, "the pair
`pr a x` lies in `f`") requires it too. The structural `Rg` therefore reads
a domain ("x is a first component of a pair of f"), exactly as T70
reported. The correction is a two-index change inside `sndIn`
([Condensation.lagda.md:386-387](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md));
no use site changes, no delivered theorem changes meaning.

## 1. What `sndIn ku kw` actually asserts (independent derivation)

### 1.1 The binder conventions

Binding is by de Bruijn, primitive in the syntax:

- `∃̇∈ t φ` and `∀̇∈ t φ` take a body with one more free variable, and
  variable `0` is the one just bound ([Syntax.lagda.md:100](/Users/alsg/Agentic/Bedrock/src/FOL/Syntax.lagda.md)).
- Satisfaction pins the reading: `γ ⊨ (∃̇∈ t φ) = ⋁ S (λ x → (x ∈ˢ ⟦ t ⟧ γ) ⊓ ((x ∷ γ) ⊨ φ))`
  ([Semantics.lagda.md:103](/Users/alsg/Agentic/Bedrock/src/FOL/Semantics.lagda.md)).
  Each binder prepends its witness to the environment, so each nested
  binder shifts every outer index by one: a top-level variable `i` appears
  as `suc i` under one binder and `suc (suc i)` under two.

### 1.2 The formula, index by index

`sndIn ku kw` ([Condensation.lagda.md:383-387](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md)):

```text
∃̇∈ (var kw)            -- binder 1: x ∈ kw (x will be pinned as a singleton)
  ( sgl f0
  ∧̇ ∃̇∈ (var (suc kw))  -- binder 2: y ∈ kw (y will be pinned as a pair)
      ( pair2 f0
      ∧̇ ∀̇∈ (var (suc zero)) (var f0 ∈̇ var (suc zero))   -- (i)
      ∧̇ var (suc (suc ku)) ∈̇ var (suc zero)              -- (ii)
      ∧̇ ∀̇∈ (var (suc (suc kw))) (¬̇ (var f0 ≐ var (suc (suc (suc ku)))))  -- (iii)
      ) )
```

Key index readings (all verified against the semantics clause above and
against T70's scratch probe):

- The first binder's body shifts the original `kw` to `var (suc kw)`, so
  **the second binder ranges over members of the original `kw` again**, not
  over a member of the first-bound `x`. The two fresh witnesses under
  binder 2 sit at the small fixed indices: `var zero` is the second-bound
  `y`, `var (suc zero)` is the first-bound `x`.
- The membership conjunct (ii), `var (suc (suc ku)) ∈̇ var (suc zero)`,
  reads "the original `ku` is a member of the singleton witness `x`".
  Since `sgl f0` pins `x = ⁅ a ⁆s` (a singleton), membership in `x` is
  `ku = a`, i.e. **`ku` equals the first component of the pair `kw`**.
- The conjunct (iii), `∀̇∈ (var (suc (suc kw))) (¬̇ (var f0 ≐ var (suc (suc (suc ku)))))`,
  reads "no member of the original `kw` equals `ku`", an inequality clause
  over the pair itself.

### 1.3 The verification instance

Take the Kuratowski pair `p = pr ∅ one` (first component `∅`, second
component `one = ⁅ ∅ ⁆s`). The current formula satisfies
`⟨ (∅ ∷ p ∷ []) ⊨ sndIn f0 (suc zero) ⟩`: the witnesses are the singleton
member `x = ⁅ ∅ ⁆s` and the pair member `y = ⁅ ∅ , one ⁆`, and the
membership conjunct (ii) is `∅ ∈ x`, which holds exactly because `∅` is
the FIRST component. This is machine-verified by T70's scratch probe
(`/tmp/T70SndIn.agda`, `claim` at the file's end, typecheck exit 0): the
two candidate readings differ here, and the formula picks the first
component. The intended reading would require the membership conjunct to
hold against the pair member `y` (i.e. `one ∈ y`, the second component),
which the current conjunct does not state.

**D-10 verdict on T70's reading: it is correct.** Re-derived independently
of T70's report, from the syntax, the satisfaction clause and the
concrete instance; no reliance on the report's own probe beyond using its
file as the recorded witness.

## 3. Verdict: comment or code?

**Code.** The comment states the intended meaning, the name `sndIn` ("the
second component is in") agrees with it, the sibling atoms `fstEqTo`
([Condensation.lagda.md:363-365](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md))

targets the wrong witness: `var (suc zero)` (the singleton member, first
component) instead of `var f0` (the pair member, which contains the second
component).

## 4. The correction, and what it costs

Inside `sndIn` only, two index changes
([Condensation.lagda.md:386-387](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md)):

1. Membership conjunct (ii): `var (suc (suc ku)) ∈̇ var (suc zero)` becomes
   `var (suc (suc ku)) ∈̇ var f0`, so `ku` is asserted a member of the pair
   member `y`, not of the singleton `x`.
2. Inequality conjunct (iii): `∀̇∈ (var (suc (suc kw))) (¬̇ (var f0 ≐ var (suc (suc (suc ku)))))`
   becomes `∀̇∈ (var (suc zero)) (¬̇ (var f0 ≐ var (suc (suc (suc ku)))))`, so
   the inequality ranges over the members of the singleton witness `x`
   (whose only member is the first component `a`): under this third binder
   the original `ku` sits at `suc (suc (suc ku))`, and the clause excludes
   `ku = a`, thereby forcing `ku` to the second component:
   `ku ∈ y ∧̇ ku ≠ a` with `y = ⁅ a, b ⁆` gives `ku = b`.

The binder skeleton, `sgl`, `pair2`, the `x ⊆ y` conjunct (i), the use
sites, and the Δ₀ witness `sndInΔ₀` ([Condensation.lagda.md:389-392](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md))
all keep their shape: the delta witness is a type-level claim about the
formula's bounded shape, not about its variable indices, so it remains
green. The same two changes apply to the probe's copy
([ProbeLevy.agda:76-80](/Users/alsg/Agentic/Bedrock/src/ProbeLevy.agda),
untracked scratch).

**Pricing (both calibers).** Naive: one clause edit plus re-verification of
the binder arithmetic, under 10 non-blank in-fence lines of change.
Calibrated (the project's measured 1.3x on a probe- or comparable-anchored
part): about 13 lines; the dominant cost is not the edit but the
re-derivation of the indices, which is the exact work done in section 1
above. No new dependency, no new gate, no interface change.

**What breaks if the code is corrected? Nothing that is delivered.**
Changing `sndIn` changes the meaning of exactly the statements that
compose it: `sndIn` itself, `snd∈Snd`, `limIn` (and through it the limit
clause `limitForm` and `Ap`), and `Rg` (and through it `levelStory`, hence
the transported `σᴹ` at [Condensation.lagda.md:589-590](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md)
and `σL` at [Condensation.lagda.md:644](/Users/alsg/Agentic/Bedrock/src/L/Condensation.lagda.md)).
None of those is a delivered theorem with a semantic claim: the chapter
delivers the certificates (`levelΔ₀`, `levelΣ₁`, `levelΠ₁L`, the transfer
lemmas), which are syntax- and transport-level statements that survive the
index change verbatim, and the adequacy decodes that would give the story
its meaning were priced as row (c) work and are not delivered (T70
report, section 2 item 3). The GCH-critical claim is precisely the one at
risk here: the delivered story's range read currently asserts a domain
read, so no inference from `levelStory` to "x is in the range of f" is
valid today; after the fix it is. The correction therefore changes no
delivered theorem's meaning and repairs the meaning of the undelivered
one.

## 5. Naming

`sndIn` is a fine name for the intended clause ("the second component is
in"), and after the correction it does not mislead. The trap was not the
name but the code reading a first component under a second-component name.
The comment should be sharpened to match the code's actual meaning once
fixed: "var k is the second component of var l (var l a Kuratowski pair)",
parallel to `fstEqTo`'s "the first component of var k equals var a", since
the clause asserts equality (`ku = b`), not mere membership in the second
component.
