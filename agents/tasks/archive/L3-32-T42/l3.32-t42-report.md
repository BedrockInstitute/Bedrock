## 2. D-10: the targets, checked for truth before proving

**Target A1 (from T14): "the per-level order as an element"**, at each level
an element `orderAt α` with the pair-membership read
`pr x y ∈ orderAt α ⟷ Sset-below α x y`, and the level membership (SZ
1.11(1)'s "in particular `<^A_β ∈ J_α`").

Truth check, at the intended generality (variable `α`, `IsOrd α`):
1. T19 already recorded the recorded T3 ("the order as an element at
   `sucV C₀`") as unbuildable, with the correction "the order at `C₀` as an
   element of `Sset (sucV C₀)`". That corrected statement still needs the
   order formula at `C₀` (chapter B): the pair set is a *definable* subset
   of `Sset (sucV C₀)` (each pair `pr x y` of members of `S_{C₀}` is a rud
   value one level up, via `F9`), so carving it requires B's σ_< formula and
   the definable-set/satisfaction face; the exact level offset is a
   B-discharge question (SZ's J-tower statement carries an ω-block of slack,
   `sz-full.txt:330-337`).
2. NEW finding this batch: the natural formula-free definition of the pair
   set as a restricted `sett` over the small index cannot be formed at all.
   `sett`'s index must be a `Type ℓ`, but the order comparison
   `Sset-below` lives at `Type (ℓ-suc ℓ)` (the SWO relation level), so the
   restricted Σ-index family is one universe up and unavailable. The
   internalization therefore must go through the object-language formula
   (B) and the definable-set face; there is no meta-level shortcut.
3. Correction recorded and built: chapter A fixes the *interface* `OrderAtAt`
   (with the honest level-membership field `orderAt-in`, T19's reading), and
   proves what needs no formula. The residue for B is named: the formula
   whose definable set is `orderAt α`, discharging `OrderAtAt`.

**Target A2 (from T14): "the family table ⟨<^A_γ⟩_{γ<β} ∈ J_α"**, the
sequence of orders below `β` as one set, and its placement in later levels.

Truth check:
1. The family IS formable at the small index: `orderTable β =
   sett ⟪ β ⟫ (orderFam β)`, the W2 pattern (`Hierarchy.lagda.md:480-483`),
   with membership read both ways at the small index. This needs no formula
   and is delivered.
2. The placement claim "∈ J_α" for the *set itself* is not provable at the
   delivered face without B: a level is transitive, so a table that were a
   member at a level would have all its entries there (they are, via
   `orderAt-in` and cumulativity, at `Sset (sucV β)`), but the *set* of
   entries is a definable subset of `Sset (sucV β)` and the S-tower absorbs
   definable subsets only through the satisfaction/definability machinery
   (the SZ 1.7 class, `sz-full.txt:236-245`), i.e. B plus the W1-face
   machinery. This is exactly the shape CodeSet recorded for the code set
   (`CodeSet.lagda.md:26-31, 380-420`): the family exists, the placement is
   a definability discharge.
3. Correction recorded and built: chapter A delivers the table with its
   reads, the entry-level membership (`orderTable-level`), and the two
   assembly laws. The table's own level membership is named as B's residue.

No recorded target turned out false in a way that changed the mathematics:
both corrections are *placement* corrections (which chapter proves the
placement), consistent with T19's D-10 record and T14's "A-full after B".

## 3. Did T22's prescription hold under real construction? Cure by cure.

The batch's question is whether the T22 first-formulation cures survive real
construction. Answer: **yes on every cure that was triggered, and one cure
was never triggered, which is itself the batch's positive finding.**

1. **Never `with` on a transparent least-witness term; named helper with a
   written type carrying the equation (I-5).** NOT TRIGGERED. Chapter A's
   proofs never case a key-derived term: every least-witness contact is
   absorbed by the interface's pair-read fields (`orderAt-pair-in`/`-out`)
   and the delivered `order-agrees`. The one place a `with`-shaped
   decomposition might have appeared (proving the pair-read from the order)
   is exactly what B must discharge. Finding: the interface is the seal that
   keeps the search out of chapter A's obligations, so the search cost stays
   entirely in B, where T22 already measured the cure.

   its birth site (R-38), read through opaque-unfolding lemmas (R-36).**
   HELD. `orderTable` is sealed `opaque` at its birth site with the two

   every consumer (`orderTable-level`, `orderTable-cover`, `orderAt-limit`)
   uses only the reads. No wall; the pattern is the CodeSet one, applied to
   orders.
3. **State memberships and comparisons at the small index (R-35), pin every
   presentation implicit (I-4).** HELD. The pair-read `orderAt-small` is at
   `⟪ Sset α ⟫` with the presentation head explicit; the table is at
   `⟪ β ⟫`; no concrete tower index is ever formed in an obligation. Two
   refinements the construction forced (below) are in the same family:
   record fields must not carry `⋃`-headed level types, and `mem-ord`'s

4. **Take ordinals as variables, ordinality as a separate hypothesis
   (R-37).** HELD and strengthened: every statement is `(β : S) (ordβ :

   strengthening was forced by cure 3's refinement (the family must not
   compute `mem-ord` inside the table's index family).
5. **Re-home truncated search results into proposition-valued goals.** HELD.
   The table's membership is itself the truncation, so both reads land in
   propositions; every `PT.rec` elimination in the limit assembly lands in a
   proposition (`⟨ z ∈ˢ (⋃ (orderTable β)) ⟩`), and `member-in` absorbs the
   `Sset-limit` truncation into a proposition-valued goal.
6. **Write every branch type that reaches a comparison or a search.** HELD.
   Every `PT.rec`/`PT.map` branch is a named `where`-function with a written

   `entry-step`, `pair-step`, `go1`-`go3`); no bare lambda carries a
   truncation branch.

**Net:** the prescription is construction-viable; its cost in this chapter

## 4. Walls: what reappeared, what appeared, and what each cost

T19's three walls did **not** reappear under this protocol:

  `orderAt-limit` transport `order-agrees` at variable levels throughout.

Two walls **appeared that T22 did not name**, both storage-position and
inference traps already present in the law book but not in T22's cure list:

1. **Record fields carrying `⋃`-headed level types (the R-35/GLp storage
   class).** A `record` whose field type mentions `Sset (sucV α)` (which
   unfolds `sucV` = `_∪_` = `⋃`-headed) hangs: measured 219 s to heap
   exhaustion at 8 GB with the record alone in the file; the same type as a
   plain Π or as a component of a plain Σ is instant (1.1-1.3 s). This
   reproduces exactly the GLp datum appended to R-35 ("a nested small-index
   type ... is free inline but hit a 12 GB heap wall ... when stored in a
   RECORD FIELD. Storage position, not expression size, was the trigger.",
   `LESSONS.md:786-791`). Cure: the interface is a plain dependent sum, not
   a record; consumer access is by Σ projections. Cost: the longest bisect
   of the run (~2 hours, three record-field variants probed: direct
   membership, application-of-predicate, Σ-component; only the Σ survived).
2. **`mem-ord`'s implicit carrier must be written (the I-4 class).**
   `mem-ord ordβ γ γ∈β` with the implicit `{A}` leaves unsolved membership
   metas (`x ∈ _A` blocked against `x ∈ β`) in definitional checks: it
   breaks the `∣ m , refl ∣₁` table-hit pattern when the family's value
   passes through `mem-ord`, and it leaves metas on every `ordγ =
   mem-ord ordβ γ γ∈β` declaration. Supplying `{β}` explicitly cures both
   (probe-verified: implicit form leaves metas, explicit form checks in
   1.1 s). This is the I-4 mechanism (an implicit inverted through a
   record-bodied defined function is never solved) applied to `mem-ord`'s
   carrier. Cost: a second bisect (~1 hour) and a mechanical five-site fix.
   The chapter now writes `mem-ord {β}` everywhere
   (`OrderFamily.lagda.md:235, 369, 371, 379, 426`).

Cost of the walls overall: both were measurement-and-cure, not content; the
final file checks in 1.3-1.8 s wall at `-M8g` with the cures in place.
