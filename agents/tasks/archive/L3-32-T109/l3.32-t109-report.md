## 1. The safety-claim audit, row by row

The table's premise is `AGENTS.md:63` ("Most rows are enforced by a checker in
`make check`, which means forgetting them costs you a red gate, not a silent
defect"). I opened each named checker, and for the two rows where enforcement
is falsifiable I also ran it on adversarial inputs. Two rows overstate their
checker, one names an enforcer that is not a checker and is self-referential,
and one overstates a single item.

### Row: Literate Agda and i18n (`AGENTS.md:75`) - OVERSTATES, the sharpest finding

The row attributes four rules to `scripts/weave-i18n.py --check`: one master
per module, the marker grammar, shared code fences, and woven copies never
committed. What the checker actually enforces:

1. Marker grammar: partially. `lint_markers` catches stray `<!--/-->`,
   unterminated groups, unknown language codes, and markers inside fences
   (`scripts/i18n_markers.py:61, 118-122`). Verified: an `<!--fr-->` block is
   rejected (exit 1). But STYLE-i18n rule 1, "markers sit on their own line"
   (`dev/STYLE-i18n.md:36-37`), is not enforced: a marker embedded in a prose
   line is silently treated as text, and `weave-i18n.py --check` exits 0
   (test: `/tmp/t109-inline.lagda.md`).
2. Shared code fences: NOT enforced. `dev/STYLE-i18n.md:38-40` forbids
   per-language code ("conditionalising code per language is forbidden"), but a
   ` ```agda ` fence inside an `<!--en-->` group passes `--check` with exit 0
   (test: `/tmp/t109-fence-in-group.lagda.md`). The checker only flags markers
   inside fences, never fences inside groups.
3. Woven copies never committed: enforced, but by `scripts/check-probes.py`,
   not by `weave-i18n.py`. `check-probes.py:59-63` classifies `_build/` and
   `/woven/` paths as never-commit violations; `weave-i18n.py --check`
   (`scripts/weave-i18n.py:44-54`) has no git logic at all.
4. One master per module: structural, enforced by the Agda typechecker's
   module-name-equals-file-path rejection, which `check-tree.py:52-53`
   documents as deliberately not re-checked because Agda already rejects it.

So the named checker enforces maybe half of what the row claims, one claimed
rule is enforced by a different checker, and two claimed rules ("shared code
fences", "markers on their own line") are enforced by nothing. A master with a
fence inside a language group or a misembedded marker passes the gate green,
which is exactly the false sense of safety the brief warns about.

### Row: Term renderings (`AGENTS.md:76`) - OVERSTATES

The row claims `scripts/check-glossary.py` enforces "settled by a dossier,
never by choosing: use it consistently and NAME it in your report." The
checker enforces only two narrower things: known-wrong renderings on each
entry's `avoid` list (`scripts/check-glossary.py:174-186`) and an opt-in
presence safety net on standalone parallel docs (`check-glossary.py:205-230`).
Verified empirically: an avoid-listed rendering (`生成者` for "producer")
fails under a `docs/zh/` path (exit 1); a brand-new term passes silently
(exit 0). Nothing in the checker knows about dossiers, consistency, or
report-naming.

The dossier half IS enforced, but by a different mechanism that the row does
not name: `dev/ORCHESTRATION.md` section 8 states the protocol and its
enforcement point is section 6 step 7 ("dispatch the terminology dossier
before the chapter counts as landed", `ORCHESTRATION.md:224-227, 252-258`).
The row's "Enforced by" column points at the wrong tool while the "canonical
home" column correctly names the protocol. A reader who trusts the column
believes a gate catches an unchosen term; the gate only catches terms that
already have an avoid entry.

### Row: Goal status and execution history (`AGENTS.md:71`) - SELF-REFERENTIAL ENFORCER

"Enforced by: the registration rule" names a rule, not an enforcement point,
which violates the file's own standard (`AGENTS.md:60-62`: an unenforced rule
must name its gate, brief section, or review step). The phrase "registration
rule" appears nowhere else in the repository (grep over `dev/` and `scripts/`
finds it only at `AGENTS.md:71`). The real rule exists and has a real
enforcement point: `dev/ORCHESTRATION.md:162-175` ("A task is registered in
`dev/PLAN.md` before the work starts, never backfilled... Enforcement: the
PLAN commit precedes the dispatch command in the same turn") and
`dev/PLAN.md:1047` ("section 11 updated in the same commit as the status
change"). This row predates the slimming (the old table had the same phrase),
so it is a carried-over defect rather than a regression, but it is the exact
false-safety pattern the cut was supposed to eliminate and it survived the cut.

### Row: Size ledger (`AGENTS.md:72`) - MINOR OVERSTATEMENT

`scripts/ledger.py --check` genuinely validates the remaining rows (both
calibers and provenance, no inverted bands, `ledger.py:111-135`), retirement
buckets, the `owed`/`excluded` sections, and verifies that `dev/LEDGER.md`'s
generated block is current (`ledger.py:250-264`). Standing, remaining and
endpoint are computed from the tree and the declaration, so the row's first

data, not a rule, but the gloss implies it is gated.

### Row: Prose (`AGENTS.md:74`) - VERIFIED ACCURATE

- English-only inside ` ```agda ` fences: rule 6, `agda_block_violations` at

## 3. Usability of the table, and the two-audience question

The table is usable. The gloss column does its job for most rows: "Prose. The
em-dash ban, CJK full-width punctuation, corner quotes, CJK spacing and
reflow, English-only inside agda fences" tells a reader exactly whether to
open `dev/STYLE-i18n.md`, and the term-renderings gloss carries the dossier
rule inline. The ordering (binding laws first, index rows last) is defensible.
The two real usability defects are both in the "Enforced by" column:

1. It mixes three semantics with no legend: machine gates ("`lint-prose.py`"),
   process actors ("the orchestrator", "review"), and "n/a". The preamble
   (`AGENTS.md:60-62`) demands an enforcement point for unenforced rules, but
   "review" never says which review and "the registration rule" names no
   point at all (section 1).
2. Rows 2-4 bind the orchestrator only, but nothing marks them as such. A
   dispatched agent cannot tell from the table which rows apply to it; the
   split exists at section level ("Working rules for dispatched agents",
   `AGENTS.md:97-99`) but not inside the table.

The two-audience split is otherwise clean. Everything the orchestrator used to
get from this file (commit with goal code, never push without the owner's
word, unblocked naming at returns, full-gate batching) is present in
`dev/ORCHESTRATION.md` and reachable through the pointer at `AGENTS.md:98-99`.
The one thing the orchestrator lost here is the glossary-entry prohibition
(section 2, item 1), which the dispatched-agent half needed and which no
longer exists in either audience's document.

## 4. Worthwhile additions (at most three)

1. **Make the enforcement column honest in rows 4, 8 and 9.** Name the real
   enforcers: goal status -> "ORCHESTRATION section 5 (PLAN commit precedes
   dispatch) plus review"; literate Agda -> "weave-i18n.py --check (markers);
   check-probes.py (never-commit); review (own-line markers, shared fences)";
   term renderings -> "check-glossary.py (avoid + presence); ORCHESTRATION
   section 6 step 7 (dossier dispatch)". Evidence for each is in section 1.
   This is the fix that makes the file's own premise true.
2. **Restore the glossary-entry prohibition** as one clause in the Term
   renderings row: "never add a glossary entry yourself; the dossier ends with
   the owner ruling." Evidence it is needed: the rule existed at
   `78245a8^:AGENTS.md:310-311`, survives nowhere else (grep), and its absence
   leaves the owner-ruled protocol in `ORCHESTRATION.md:234-258` with no
   agent-facing teeth.
3. **Add the zh/ja cross-check to the translation half** of the Boundaries
   section: "author every document in English first, then translate, then
   cross-check the Chinese and Japanese against each other for drift."
   Evidence: it is a load-bearing QA step the project already depends on
   (`dev/PLAN.md:815`, `dev/STYLE-agda.md:270`), the presence check exists
   precisely because renderings drift between translations
   (`check-glossary.py:193-200`), and the current rows point at no document
   that contains it.

## 6. Verdict

Better-with-named-fixes, with the fixes being mandatory rather than optional.

The cut's real gain is verified: the always-on body dropped from 3,450 to
1,784 words, and the largest moved blocks are genuinely safe to move. The
Prose row is fully machine-enforced and I confirmed it on adversarial input;
licensing, deployment and taxonomy are informational and correctly
indexed; the dispatch, registration, commit and push rules all have real homes
in `dev/ORCHESTRATION.md`. The calibration numbers 3,450 and 1,784 reproduce
exactly.

But the slimming's justification, the sentence the file now opens with ("a
checker enforces it"), fails on its own table. The Literate Agda row names a
checker that enforces at most half of what the row claims, and two of its
claimed rules are enforced by nothing at all. The Term renderings row names
the wrong enforcer for its headline rule. The Goal status row names a
registration rule that does not exist under that name anywhere else. These
three rows convert stated rules into a false sense of safety, which is worse
than the long version for exactly the rules that moved. One binding
restriction (the glossary-entry prohibition) was lost outright, one QA step
(the zh/ja cross-check) was weakened to near-invisible, and the two supporting
numbers (3,834 and 1,292) do not reproduce from the tree.

The slimmed file is better than the old one for every row except 4, 8 and 9,
and those three are fixable in place (section 4, items 1 and 2). Accept it
only after the enforcement column is corrected, the glossary-entry clause is
restored, and the 3,834/1,292 figures are either recomputed reproducibly or
dropped from the record.
