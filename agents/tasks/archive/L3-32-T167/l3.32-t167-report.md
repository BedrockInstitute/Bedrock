### C1. The per-op description scaffold

The eight `FᵢDesc` modules in Describe repeat the same frame: three module
headers, the fiber pair `mₐ`/`qₐ` (and `m_b`/`q_b`), and the wrapper
`extensionality (DefA.defSet Φᵢ) (Fᵢ ...) (sub₁ , sub₂)` with
`sub₁ = Ch.defSet⊆ Φᵢ dΦᵢ (Fᵢ ...) Fᵢ-desc-out`. Switch's `Descr.described`
(`src/L/Rud/Switch.lagda.md:408-432`) packages exactly this wrapper from the
two directions `din` and `dout`. Bridge already consumes it with Describe's
own modules (`src/L/Rud/Bridge.lagda.md:192`, `:226-233`), so the mechanism
is proven in-tree. The only obstacle is the dependency direction: Switch imports
Describe, so the frame must move to a master both can import.

**D22 probe.** Copy the `Descr` module and its `Chain` and `DefOf`
dependencies into a shared master. Convert one module, `F1Desc`
(`src/L/Rud/Describe.lagda.md:461-524`), to call `described`. Typecheck
Describe. Measure the removed header, fiber, and wrapper lines. Apply the
same change to the other seven modules only if the first one checks green.

### C2. The formula coding scaffold

Both `FOL.Coding` and `FOL.Count` write the same twelve-constructor skeleton:
`tagOf` with the same twelve values, `shape` with twelve `refl`, `Match` with
twelve clauses, `matches` with twelve `refl`, and a twelve-clause
injectivity proof (`go` at `src/FOL/Coding.lagda.md:386-417`, `peel` at
`src/FOL/Count.lagda.md:256-288`). The clauses differ only in the payload
type (`S` with `pr` and `⌜⌝ᵗ` in Coding, `ℕ` with `pair` and `tcode` in
Count) and in the pairing injectivity lemma. The carrier is a `FormulaCode`
record: the code type, a pairing with injectivity, and a term coding.

**D22 probe.** Write the record in a scratch master. Instantiate it at `ℕ`
with `pair` and `pair-inj`, and port Count's scaffold to it. Typecheck

to Count's arithmetic content, the carrier is viable. If the `ℕ` instance
does not fit, the scaffold is a fixed shape, and the yield is the `S`
instance only.
