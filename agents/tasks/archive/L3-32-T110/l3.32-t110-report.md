## 3. Every threshold and its argument

The counting unit everywhere is whitespace tokens (`str.split()`), the same
unit as `wc -w` and the one `[T108]`'s reconciliation used, so a threshold and
the measured failure are the same caliber.

**`agents-size`: 2,200 words.** The current green file is 1,784 words
(`wc -w AGENTS.md`, and the post-slim figure `[T109]` was told to recompute).
The failed state was 3,450, i.e. 1.94x the green file. A cap of 2,200 is 23
percent above green, which is wide enough for a legitimate single edit (a
table row, a boundary sentence: tens of words) and 1,250 words below the
failure, so the check would have fired on the decayed file with room to spare.
The file is auto-loaded into every session, so the cap is a context budget,
not a style preference: 2,200 words is the current file plus roughly one
screen, and the failure cost the project 1,666 words of always-on context.

**`plan-cell-size`: 1,600 words per cell.** Measured on the current tree: the
largest cell is `L3.32-F5` at 1,125 words; the largest ruling-class cell in
section 3 is `D28` at 572; the failed `L3.32` cell was 12,634, 11.2x the
current maximum. A cap of 1,600 is 42 percent above the current maximum and
7.9x below the failure, so it does not fire on any cell that exists today
(the gate stays green) and the failure class is unmistakably caught. The
taxonomy argument: a PLAN row is a ruling plus a status pointer, and a cell at
1,600 is nearly three times the largest ruling ever written, so anything above
it is a document inside a table, which the JOURNAL taxonomy reserves for
dev/JOURNAL.md. The sweep line of 600 is argued separately in section 6.

**`lessons-imported-routing`: no number, an invariant.** Imported entries are
the risk class: they arrive whole from outside with no local measurement that
forces discovery, which is exactly how the conversion-explosion playbook sat
for five days. The marker is deliberately narrow ("imported from/into" in the
heading); code adjectives such as "imported names" (`C-21`) are not imports of
entries. Only one entry is marked today (`P-i`) and it is routed, so the gate
is green and a new imported entry that lands unrouted fails it.

**`plan-section0-date`: no number, an invariant.** The heading is the "as of"
contract; a body that describes work newer than its heading is the measured
decay ("days behind the work it described"). No calendar is involved, so the
check cannot drift into firing every morning; it fires only when the section
disagrees with itself.

**`memo-status-form`: no number, a vocabulary.** Verdict words: STANDING,
PARTIAL, SUPERSEDED, WRONG, REFUTED, NOT BUILT. The check applies only when a
`**STATUS:` header exists (form-when-present), so memos written before the
convention are not retroactively flagged.

**`agents-enforcers`: no number.** The rules table's third column must name
files that exist; a vanished enforcer would make the enforcement-point
contract a wish.

## 4. Tuning: first run on the real tree, and what changed

The trap in the dispatch was explicit, and the first run obliged:

1. **A wolf, fixed by narrowing.** The first version of
   `lessons-imported-routing` treated any heading containing the word
   "imported" as an imported entry and flagged `C-21` ("Telescope types may
   only use level-generic imported names"), which is ordinary code prose, the
   same class of wolf `check-rule-ids.py`'s author documented. The marker was
   narrowed to "imported from/into", which matches only `P-i`'s heading. The
   wolf is now a regression test.
2. **A crash, fixed.** The date regex has no capture group; the first run died
   on `group(1)`. Fixed to `group(0)` and covered by a test.
3. **A 13-item sweep, tuned to 1.** The first sweep corpus covered live docs
   and briefs but not `_build/*.md` reports, and listed 13 entries as "cited
   nowhere". Most of those ARE cited in reports (`R-24`, `R-31` to `R-33`,
   `I-1`, `I-7`, `I-8`, `C-15` to `C-20`), so the list overstated the
   "nobody noticed" class. Adding reports and `dev/literature/` to the corpus
   left exactly one entry, `C-17`, which is genuinely unrouted and cited
   nowhere: a three-day-old lesson whose provenance is a report that predates
   it. That is a true positive, and it is what the sweep is for.
4. **The mechanism stopped listing its own finding, fixed.** Once
   dev/MAINTENANCE.md and this report cited `C-17`, the sweep's "cited
   nowhere" count dropped to zero: the mechanism's own files counted as
   citations, so the sweep could clear an entry by mentioning it, which is
   circular. The maintenance document and this report are now excluded from
   the citation corpus, and `C-17` is listed again: still unrouted, and still
   only noticed by the mechanism itself, which is the true state until the
   orchestrator routes it or an independent document cites it.
5. **One true positive stays red.** `plan-section0-date` fires on the tree as
   delivered: the `## 0.` heading is dated 2026-08-04 while the section
   describes work dated 2026-08-06. This is the brief's own decay row, not a
   threshold artifact. The fix is one line in the PLAN rewrite (`[T108]`
   owns that file): set the heading date to the newest date the section
   describes. Until it lands, `make check` is red on exactly this one finding,
   which is the mechanism working.

After tuning, the gate's only finding on the real tree is that true positive;
every subcheck except `plan-section0-date` is clean.

## 5. Deliberately not automated, and why

- **Whether a memo's diagnosis was refuted.** Refutation is a reading
  judgment; no lexical rule can tell a refutation from a refinement. The
  honest enforcement point is the return audit in dev/ORCHESTRATION.md
  section 6, which must add or update the memo's `**STATUS:` blockquote in the
  same dispatch that refutes it. The gate keeps the header honest once it
  exists.
- **Whether AGENTS.md text duplicates a checker.** Duplication is a reading
  judgment. The enforcement point is the adversarial review of any change to
  the rules table (the `[T109]` pattern), plus the size cap, which keeps the
  file cheap to review.
- **Episode versus ruling classification below the size caps.** The sweep
  surfaces the candidates (section 11 cells over 600 words); the extraction
  itself is the JOURNAL surgery.
- **Struck-decision references and foreign rule IDs** were not rebuilt because
  `check-rule-ids.py` already enforces them in the gate. A second checker
  would split the canonical home, the failure this repository names most
  often.
- **No date-of-landing check for new LESSONS entries.** Without history there
  is no mechanical "new". The sweep's "cited nowhere" list is the substitute:
  a new entry starts with zero citations and surfaces until it is routed or
  cited.

## 6. Cadence

**Every commit (in `make check`).** The six gate subchecks. They are cheap
(pure-Python text reads, milliseconds), so nothing expensive entered the
commit gate; the twelve-minute Agda typecheck still runs in the background
per D28 and is untouched.

**On demand (informational, exit 0).** `python3 scripts/check-dev-docs.py
--sweep`, run at each dispatch batch and whenever a LESSONS entry lands. It
lists:

- LESSONS entries that are unrouted AND cited nowhere (the "landed and nobody
  noticed" class). First run: `C-17`.
- Section 11 cells over the 600-word episode-scale line. The line's argument:
  the largest legitimate ruling cell is `D28` at 572 words, so a status cell
  above 600 is carrying more than a ruling plus a pointer, i.e. episode-scale
  prose that the taxonomy assigns to dev/JOURNAL.md. First run: `L3.32-F2`
  (786) and `L3.32-F5` (1,125), which predate the `[T108]` slim of the main
  `L3.32` row and are the next candidates for the same extraction.

**Threshold raising.** Only the owner may raise a gate threshold; a silent
edit to the constant in `scripts/check-dev-docs.py` is a violation. Raising
requires a numbered decision in dev/PLAN.md section 3 recording the measured
reason (the new measured size class and why the old cap no longer fits), and
an entry in the threshold record in dev/MAINTENANCE.md. The sweep's 600-word
line follows the same rule.
