## THE ROUTE PANEL: DROP MERMAID ENTIRELY

Today `route_block()` emits a mermaid `flowchart TD` source string and the
panel shows it in a `<pre>`. **The mermaid was only ever needed when the
diagram was lifted from hand-written prose. It is not lifted any more: the
generator BUILDS the graph from `dev/ledger.toml`, so it owns the structure and
does not need a general layout engine.**

So: **emit the flowchart as semantic HTML with CSS, not as mermaid.** The
structure is fixed and known to the code, which is exactly the case where a
hand-laid-out CSS diagram beats a graph library.

- **Do not vendor mermaid.** A multi-megabyte bundle would swamp a 52 KB
  orientation page, and `REUSE.toml` would need a new dependency declared.
- **Do not add a network dependency.** No CDN, no external font, no fetch. The
  page is opened from disk.
- **No JavaScript.** The page has zero `<script>` tags today and should keep
  zero: CSS is enough for boxes, columns and connectors.

The graph has two independent branches, which suits a two-column layout: the
campaign branch (freeze on or off, and what each releases) and the lever branch
(five questions in order, each with its leaf populated from the lever rows).
Decision nodes should look different from outcome nodes, and a leaf that names
real levers should show them.

## THE WORKBENCH PANEL: RENDER THE HAND-WRITTEN HALF

`_build/workbench.md` is written by hand at every return, by owner's ruling,
and is currently dumped into a `<pre>`. It has a stable shape, four
all-capitals section headings, each followed by indented items:

```
DISPATCHED NOW
QUEUED, AND WHAT RELEASES EACH
CONDITIONS THAT WOULD CHANGE WHAT I DISPATCH
NOT DISPATCHING, AND WHY
```

Parse those four headings and render each as its own block. The items under
`QUEUED` and `CONDITIONS` use `<-` and `->` to separate a thing from its
release condition or consequence; split on those and lay the two sides out so
the relationship is visible at a glance.

**Be forgiving.** This file is hand-written prose and its shape will drift. **If
a heading is missing or an item does not split, fall back to showing that part
verbatim rather than dropping it or crashing.** Losing a line the orchestrator
wrote by hand is the worst failure available here.
