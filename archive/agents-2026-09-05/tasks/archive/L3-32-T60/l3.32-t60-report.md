# [L3.32-T60] Which remaining disciplines can be tooled, and which must not be

Survey report. Rule surface: `AGENTS.md`, `dev/ORCHESTRATION.md`, `dev/PLAN.md`
(section 3, 6.0, 6.2, 7), `dev/LESSONS.md` (about a hundred entries),
`dev/STYLE-agda.md`, `dev/STYLE-i18n.md`, `scripts/` and the `Makefile`.
Every load-bearing claim carries `file:line`. Prototype scripts live in
`/tmp/t60-prototypes/`; the commands and raw output are in section 6 so every
hit count can be re-derived.

## 1. Verdict

I catalogued roughly 260 individual rule statements across the six documents:
about 44 in `AGENTS.md`, 24 in `dev/ORCHESTRATION.md`, 37 in `dev/PLAN.md`
(20 standing decisions in section 3, 6 in 6.0, 3 in 6.2, 8 in section 7),
102 in `dev/LESSONS.md`, about 49 in `dev/STYLE-agda.md`, and 6 in
`dev/STYLE-i18n.md`.

Of those, about 40 are already tooled (the prose linter, the marker checker,
the Agda-style subset, the glossary checker, the ledger checker, the
never-commit gate, the dispatch-time wrapper, `reuse lint`, and the Agda
typechecker itself, which machine-enforces at least two lessons the linters do
not: I-3's opaque type-ascription rule and C-20's mixfix rejection). About 200
must stay documentation discipline: they are judgment rules (is this the ideal
form, is this the widest unmeasured term, is this the right rendering),
process rules for the orchestrator, or proof-writing techniques that only a
scope-aware typechecker could enforce and whose false-positive cost is
conversion-wall noise. This report recommends tooling exactly 8 rules, all
with measured hit counts, and treats "leave it as documentation" as the answer
for the rest.

**The single proposal to build first: the Everything import-closure audit.**
PLAN section 7 rule 3 (dev/PLAN.md:971-975) says an audit script asserts on
every check that the import closure of `Everything` equals the set of `src`
masters. No such script exists (see section 5). This is the project's one
documented false-green mode, the predicate is trivially decidable, and the
prototype measured exactly one gap on the real tree (the untracked, in-progress
`src/L/Rud/OpGraph.lagda.md`) with zero false positives.

### 2.1 Notes on the recommended set

**1 (closure).** The predicate needs the exemption that `Everything` itself is
the root, and it must scan the working tree (like `lint-agda.py`,
scripts/lint-agda.py:361-365) so a new untracked master cannot escape. The
measured gap today is exactly one master, `L.Rud.OpGraph`, which is untracked
work-in-progress, so the check is green on committed content and would have
caught the file the moment it was added. The failure message must name the
missing module and the fix (`import L.Rud.OpGraph` in reading order). This is
the false-green mode PLAN 7.3 exists to close, and today it is enforced by
nothing (section 5, gap 1).

**2 (archive boundary).** The archive currently holds one module
(`archive/src/L/Rud/Realize.lagda.md`), so the check is green; it will matter
at the `[L3.32]` retirement surgery, when the archive grows. The predicate
uses the module names declared in archived masters, not paths, and only flags
imports of modules that exist nowhere in `src/` (a re-created module with the
same name is a revival and is legal). The other half of D20, "archived files
are frozen", is decidable only through git history (no archive file modified
after its archival commit) and is left as documentation plus this boundary
check.

**4 (naming shapes).** Predicate (b) is deliberately scoped to column-0
declarations only. The tree carries 192 distinct primed identifier tokens,
almost all indented locals, which are the sanctioned twin use
(dev/STYLE-agda.md:136-139); a broader prime ban would fire on most of them.
The column-0 scope finds exactly the public-name violations, of which there is
one today: `u' : V ℓ → V ℓ` at src/L/Rud/Step.lagda.md:93. Predicate (a)
found `import Cubical.Functions.Logic as L` at src/L/Godel/Name.lagda.md:68,
which collides with the book's subject `L` exactly as dev/STYLE-agda.md:128-130
forbids. Predicates (c) and (d) are currently green. Constructors and record
fields with primes remain review-enforced (the same scope limitation that
`lint-agda` documents for itself at scripts/README.md:32-34).

**5 (PLAN status).** The refined predicate excludes history annotations in
parentheses ("(was ACTIVE 2026-07-26)", "This row read PLANNED until
2026-07-28", dev/PLAN.md rows L3.16 and L3.17), which my first pass misread as
2 false positives. The 7 TRUE hits are the rows that open with a non-terminal
status and later state a terminal one: L3.0.1 (`RE-POINTED` ... `DONE`), and
L3.22, L3.23, L3.24, L3.25, L3.26, L3.28 (all `REGISTERED` ... `DONE`). These
are exactly the C-7 failure class, which was measured to have happened five
times before and to have double-counted projections for a day
(dev/LESSONS.md:1692-1696). The vocabulary itself is a separate finding: 19 of
86 rows open with a word outside the six registered statuses (section 5, gap
4), so the check must be ratified against the owner's preferred vocabulary
before it can also gate on the vocabulary.

**6 (CJK in shared prose).** This closes the documented blind spot in C-8
(dev/LESSONS.md:1704-1708): `check-glossary.py` keys off language markers, so
shared prose is never scanned for either forbidden renderings or stray CJK.
The prototype found 0 CJK lines in shared prose today, but the class is real:
shared prose is copied verbatim to every language page (dev/STYLE-i18n.md:27-28),
so a CJK sentence there would appear on the English page. The check is a
natural extension of `check-glossary.py`, which already parses the markers.

**7 (module indentation).** Agda's layout makes the common failure a compile
error (the parameter is out of scope), but the silent case, a body that never
uses the parameter and therefore parses as an empty module, typechecks clean.
The predicate catches both. 43 parameterized headers exist and all are
compliant today. This is the cheapest insurance of the set and can wait.

**8 (SPDX).** The literal string appears in exactly one file, `REUSE.toml`
(10 lines, the canonical home), plus two prose mentions of the rule itself in
AGENTS.md and PLAN that do not contain the literal header form. The check is
trivially decidable, currently green, and stops the one drift the licensing
design centralizes against (AGENTS.md:314-318).

## 5. Gaps in the existing tools

Mismatches between what the documents claim and what the tree or the tools
actually do. Each is a finding either way.

1. **The import-closure audit is documented but does not exist.** PLAN section
   7 rule 3 (dev/PLAN.md:971-975) says "An audit script asserts, on every
   check, that the import closure of `Everything` equals the set of
   `src/**/*.lagda.md` files." Nothing in `scripts/` or the Makefile computes
   this (no script mentions the closure; the `make check` target list is
   Makefile:36). The prototype shows why it matters: the closure currently
   misses `src/L/Rud/OpGraph.lagda.md`, which is unchecked by the one trusted
   gate. The `Everything` import list is hand-maintained
   (src/Everything.lagda.md:20-140), and PLAN 7.3's "audited away" claim rests
   on nothing today.
2. **Prose and glossary scans are git-index based; the Agda linter is not.**
   `lint-prose.py` and `check-glossary.py` discover files through
   `git ls-files` (scripts/lint-prose.py:426-437, scripts/check-glossary.py:285),
   while `lint-agda.py` globs the working tree (scripts/lint-agda.py:361-365).
   A new untracked master, like today's `src/L/Rud/OpGraph.lagda.md`, is
   covered by `lint-agda` and the marker checker but silently skipped by prose
   and glossary in `--check` mode. C-8 documents exactly this blind spot
   (dev/LESSONS.md:1704-1708). The fix is a working-tree scan in the two
   index-based tools; the pre-commit hook's staged coverage is the current
   mitigation.
3. **STYLE-agda section 7's `-- perf:` discipline is 86% unenforced and the
   tree does not follow it.** The rule (dev/STYLE-agda.md:238-242) requires a
   `-- perf: <trigger>` marker on every countermeasure and says narration
   never explains them. Measured: 155 `opaque` blocks in the agda fences, 134
   without a marker within 3 lines, and several chapters explain seals in
   prose instead (e.g. src/L/Axioms/Basic.lagda.md:152-155), which the rule
   says is exactly backwards. Either the rule is narrower than written (some
   seals are structural) or the tree needs a one-time sweep. The mismatch is a
   finding in both directions.
4. **The registered status vocabulary does not match the registry.** PLAN 6.0
   rule 5 (dev/PLAN.md:557-559) lists PLANNED, ACTIVE, DONE, PARKED,
   SUPERSEDED, ABANDONED. The section 11 table opens rows with SUSPENDED,
   RE-POINTED, STANDING, CLOSED, DISSOLVED, REGISTERED and "RULED AND ACTIVE"
   (19 of 86 rows). The owner should either ratify the wider set or the table
   should be brought back to the six; until then only the staleness half
   (RECOMMENDED 5) is gateable.
5. **The section 11 table is not linted at all** despite being the project's
   live status board; C-7's failure class was measured once (five stale rows,
   dev/LESSONS.md:1692-1696) and nothing has changed since. This is the gap
   RECOMMENDED 5 closes.
6. **The one-check-per-language marker gap is real but currently benign.**
   `check-glossary.py` never scans shared prose (its language scoping at
   scripts/check-glossary.py:116-140 returns "shared" for marker-free lines),
   and the shared-prose CJK check (RECOMMENDED 6) found 0 current hits. The
   tool's own README documents the marker-keyed scope
   (scripts/README.md:101-104).
