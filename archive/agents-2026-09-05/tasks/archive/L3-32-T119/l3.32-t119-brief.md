## THE EIGHTEEN, HONESTLY

**Mechanised: the tool now refuses these.**

1. **`wait --all` armed on every dispatch.** It blocks until the SLOWEST agent,
   so a fast return sits unnoticed. Two returns sat behind a long one. FIX:
   `--all` refuses when more than one agent is live.
2. **Five waiters stacked**, each with its own watch set; a stale one can
   consume a return by marking it `reported`. FIX: singleton.
3. **A model the backend rejects** (`deepseek-v4-pro`), two agents died
   silently. FIX: date-gated block, checked in `launch()` so `run`, `queue` and
   `resume` all refuse.
4. **A report-writing brief under `-s read-only`**, which blocked the report.
   FIX: validator refuses.
5. **TaskStop on the watcher killed two live agents** in its process group.
   FIX: `start_new_session=True`.
6. **The watcher counted itself** (`pgrep -f 'bin/codex exec'` matched its own
   command line), leaving slots idle. FIX: explicit PID watching.
7. **stdin deadlock**: codex reads stdin, a backgrounded launch inherits a pipe
   that never closes; one agent burned 13 minutes on a 0-byte log. FIX:
   `stdin=DEVNULL`.
8. **A full gate run while agents were mid-write**, giving a spurious red and
   risking a spurious GREEN. FIX: `gate-ready` refuses while agents are live.
9. **A brief with no checkable evidence requirement.** FIX: validator refuses,
   accepting `file:line` OR a citation URL.
10. **A waiter spending its single report on an already-announced return**,
    leaving the live agent unwatched. FIX: skip anything in the durable log.

**Not mechanised, and this is where the review should push.**

11. **Arming with `&` inside a compound Bash command** instead of a tracked
    background job. The waiter runs, watches correctly, prints into a pipe
    nobody reads, and marks the return reported. Cost 32 minutes.
    **A detector was written and REMOVED the same session**: it used fcntl
    F_GETPATH to refuse arming when stdout was not a harness task file, but
    from inside the process that case is indistinguishable from the correct
    one, because the arming command is routinely piped through `tail`. It
    refused to arm in exactly the case it must arm in. Caught today only by the
    durable log and by `status`'s NO WAITER banner.
12. **Forgetting to re-arm after each return.** Partially covered: `run` and
    `status` shout when agents are live and no waiter is armed. Nothing forces
    it.
13. **Two live dispatches claiming the same write territory.** The orchestrator
    prevents this BY HAND, writing "Never: X, agent Y holds it" into every
    brief. **Nothing checks it.** Grep the dispatcher: territory appears only
    in comments.
14. **A design recon that ran nothing, recorded as a finding.** One recon
    reasoned in prose that a cure would transfer, said honestly that it had
    typechecked nothing, and the orchestrator wrote its conclusion into the
    register as "overturned" before any measurement. A later dispatch measured
    it and restored the original verdict. Nothing distinguishes a MEASURED
    claim from an ASSERTED one in a brief or a return.
15. **A brief stating a false load-bearing fact.** One brief asserted "no
    script reads dev/LEDGER.md"; a script read it unconditionally. The brief's
    own D-10 clause caught it because the orchestrator happened to ask. Nothing
    requires the author to mark which of its own claims are unverified.
16. **Task codes registered late**, back-filled after a checker caught them, on
    every dispatch of the last eight. The checker catches it at commit time,
    not at dispatch time.
17. **Gate races**: editing the ledger while a full gate reads it, twice, each
    costing a full twelve-minute gate. Recorded as prose in ORCHESTRATION with
    the orchestrator as the enforcement point.
18. **A check that could not distinguish the failure from the correct usage**,
    written and removed the same session (this is number 11's detector).
    Recorded, not prevented.

## WHAT TO ACTUALLY DO

### 1. Extrapolate, which is the dispatch

For each mechanised fix, ask **what ELSE has that shape and is not covered.**
Concretely, some directions, and you should find others:

- Number 2 fixed stacked waiters. **What other state in `.state/` can go stale
  or be written by two processes at once?** The registry is read-modify-written
  under a lock; is every path locked, including `resume` and the `reported`
  flag updates?
- Number 3 blocks one bad model by name and date. **What other launch argument
  can be silently wrong?** The sandbox, the working directory, the brief path
  that exists but is the wrong brief.
- Number 8 refuses a gate while agents are live. **What else must not run
  concurrently?** Two Agda profiles corrupt each other's measurements, and this
  campaign funds decisions on those numbers.
- Number 10 stops a waiter wasting its report. **What else consumes a
  one-shot resource?**

### 2. Attack the three biggest uncovered gaps

**Write territory (13)** is the one the orchestrator most relies on discipline
for. Every brief hand-writes its exclusions. Design the check: what would it
read, what would it refuse, and what false positive would make it useless?
Note that briefs live in `_build/briefs/` and are not committed.

**Asserted versus measured (14, 15)** is the one that cost the most rework. Is
there a mechanical form? Consider: a brief could be required to mark each
"established fact" it hands the agent with how it was established, and a return
could be required to mark each finding as measured or reasoned. Would that
survive contact, or become a ritual nobody reads?

**Arming (11, 12)** resisted one detector already. **Do not propose that
detector again.** Ask instead whether the arming can be made unnecessary, or
whether the RECOVERY can be made so cheap that the failure stops mattering.

### 3. Judge the fixes that exist

Two of the eighteen were fixed badly:

- Number 18's detector was removed. Was removing it right, or is there a
  version that works?
- Number 12's fix is a printed warning, which is the weakest kind of
  enforcement this project recognises. `AGENTS.md` says a rule whose
  enforcement point is a person's intention is a wish. Is that warning a wish?

**And find a fix that is worse than the disease.** With eighteen of them added
in a day, at least one is probably over-fitted to the incident that produced it.
