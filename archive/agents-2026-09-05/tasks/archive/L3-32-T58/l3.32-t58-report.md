# [L3.32-T58] Adversarial review of the dispatch wrapper

Reviewed 2026-08-05 against `.claude/skills/codex-dispatch/dispatch.py` at
revision 14808 bytes, `.claude/skills/codex-dispatch/SKILL.md`, `dev/ORCHESTRATION.md`,
`dev/LESSONS.md` C-12, and the brief corpus under `_build/briefs/`.

## 1. Verdict

**Do not use the tool for concurrent dispatch until the registry write is serialized and the
slot check is atomic with it.** Two dispatches racing for the last free slot both launch
(three Agda agents against a ceiling of two) and one of them silently vanishes from the
registry: in a 10-way concurrent stress, all 10 agents launched but only 3 registry entries
survived. That is the tool's core data structure failing under its own documented fan-out
usage, and the loss is silent. The single most severe defect is the unlocked
read-modify-write on `registry.json` combined with the check-then-act slot count
(`dispatch.py:140` reads, `dispatch.py:145` checks, `dispatch.py:195` saves, no lock in
between, with a 0.5-20 s window while the session id is scraped).

Two further defects are severe enough to matter on every dispatch, not only concurrent ones:
`alive()` reads `PermissionError` as "dead" (`dispatch.py:69-72`), so in this environment the
census reports live agents as exited and reads 0/2 Agda slots while two Agda agents actually
run; and the dead-model block lives only in `cmd_run` (`dispatch.py:205`), so `queue` and
`resume` launch `deepseek-v4-pro` agents that die silently, recreating failure mode 1 through
the exact route the SKILL recommends.

The wrapper's core safety ideas are sound and verified: `setsid` on the child
(`dispatch.py:178`), a PID registry instead of command-line pattern matching
(`dispatch.py:75-81`), correct global-before-subcommand flag order on resume
(`dispatch.py:162-163`), the slot refusal message, and the census's live/exited/no-final
classification. They are undermined by the defects below, not by being wrong ideas.

## 4. Contract mismatches (`dispatch.py` vs `dev/ORCHESTRATION.md` / `SKILL.md`)

**The script enforces something ORCHESTRATION does not say.**

- A flat ceiling of 2 Agda slots at `-M8g` (`dispatch.py:47-49`) where ORCHESTRATION section 2
  and LESSONS C-12 (`dev/ORCHESTRATION.md:28-33`, `dev/LESSONS.md:1780-1792`) currently allow
  WIDE mode at up to 4 x `-M8g` or HEAVY mode at 2 x `-M12g`, with the tier chosen at dispatch.
  The script has no tier knob, no `-M12g` option, and no memory gate, so it both under-provisions
  (a 4-slot WIDE batch is refused even when the machine is empty) and silently omits the
  law's memory gate and watchdog backstop (the script only sets `GHCRTS`; it never checks free
  memory and never invokes `_build/tools/agda-watchdog.sh`).

**The script silently permits what ORCHESTRATION requires.**

- An Agda agent escaping the ceiling by omitting `--agda` (demonstrated): ORCHESTRATION's slot
  rule binds the agent's actual behavior, but the script can only trust the flag and does not
  even cross-check the brief for Agda work.
- ORCHESTRATION section 3 (`dev/ORCHESTRATION.md:43-59`) requires each brief to carry CWD,
  SCOPE (read) in order, SCOPE (write) naming every writable file, disjoint territories,
  CONSTRAINTS (heap cap, one Agda process, no git, stop-line), and the D-clauses. The script
  validates only `tier:`, RETURN, `file:line`, and the write-order/sandbox rule
  (`dispatch.py:105-135`); a brief with none of CWD/SCOPE/CONSTRAINTS passes (D15).
- ORCHESTRATION section 1 (`dev/ORCHESTRATION.md:23-26`) requires a `tier: opus` to name its
  exception; the script checks only that a `tier:` line exists (`dispatch.py:115-117`), so
  `tier: opus` with no justification passes.
- Pinning: ORCHESTRATION says pinned in `_build/briefs/` (`dev/ORCHESTRATION.md:45`); the
  script checks only that the parent directory is literally named `briefs`
  (`dispatch.py:110-112`), so `/tmp/briefs/` passes (D15).

**SKILL promises the script does not keep.**

- `SKILL.md:43`: "it records the session id at launch so a resume is always possible" is false
  for late or never-printed ids (D11).
- `SKILL.md:188-189`: "dispatch.py enforces the ceiling itself, so this cannot over-subscribe"
  is false under concurrency (D1).
- `SKILL.md:31-39` (the refusal table): the table implies the dead-model refusal applies to the
  whole command surface; `queue` and `resume` bypass it (D3), and `queue` also never refuses a
  report-writing brief whose file is edited after queueing (D8).

## 5. What I could not test, and what would be needed

- **Real `codex exec` launches.** Every launch was through a fake `codex` on PATH that logged
  argv/env and lifecycle markers; no real agent ran, so the real CLI's session-id timing, its
  `-o` behavior, and the claimed flag-order constraint on `resume` (`dispatch.py:157-163`)
  were verified only by construction and by the SKILL's own measurement. Needed: one real
  `run` and one real `resume` against a scratch state dir, on an idle machine.
- **Real `ps` output on this machine.** `ps(1)` is denied by this sandbox (`PermissionError:
  Operation not permitted: 'ps'`), so the macOS `MAXCOMLEN` (16) truncation of
  `codex-darwin-arm64` (18 chars) is asserted from documented OS behavior and demonstrated by
  mocking a truncated comm (`strays: []`), not measured against the real binary. UNVERIFIED
  claim: on real macOS `ps -o comm`, the needle `codex-darwin-arm64` may never match. Needed:
  one run of `ps -A -o pid=,comm=` on the host without the sandbox.
- **The EPERM liveness condition from the orchestrator's own context.** The D2 misreport is
  demonstrated from this agent's sandbox (T54/T56/T58 EPERM-alive, reported exited). Whether
  the orchestrator's Claude Code session enjoys kill rights over its launched agents is not
  measurable from here. Needed: `dispatch.py status` from the orchestrator while two agents run.
- **Kill-based exit scenarios.** Cross-`exec` signalling is denied here, so "killed agent"
  cases were simulated with short-lived fake agents (semantically identical for the registry
  logic: pid dead, no final message). Process-group kill behavior of the real child (the
  setsid fix) was not re-tested. Needed: a real agent, killed from a watcher, checking the
  child survives.
- **Real `deepseek-v4-pro` API rejection.** The block is measured elsewhere
  (`dispatch.py:41-43`); I did not call the API.
- **Race probabilities.** The slot race is deterministic (both readers beat both writers);
  the lost-update rate was quantified by stress (7/10 in one batch, 1/2 in the two-racer run)
  but depends on the scrape timing. Needed: repeated runs on real timing to bound it.
