## 2. The pin frame's shape and cost

The frame is a module `PinFrame`, parameterized at the carrier and the arm
arguments (P-h). The formula is:

```
body i = (var f0 ≐ var f3) ∧̇
  ((var f1 ≐ con m_b) ∧̇ ((var f2 ≐ con mₐ) ∧̇ memOf i))
pinned i = ∃̇ (∃̇ (∃̇ body i))
```

`memOf i` reads the environment `(z, b, a, y)`: the member at `f0`, the
second argument at `f1`, the first argument at `f2`, the value slot at
`f3` (StepGraph.lagda.md:609, :657-658). Three existentials bind the
member slot and the two argument slots. The pins force the argument
slots to the constants `m_b`, `mₐ`. A third pin, `var f0 ≐ var f3`,
re-connects the member slot to the free tail variable. This third pin is
the refinement: `∃̇` binds the head, and `memOf` keeps the member at the
head. `AtStep`'s image formula already keeps the value at the tail, so
its `inU` shape does not transfer verbatim (StepGraph.lagda.md:1901,
:1921).

`pinned-out` and `pinned-in` are generic in `i`. They consume `memOut i`
and `memIn i` directly (StepGraph.lagda.md:1685-1727). Every truncation
branch carries a written type (I-5). The frame costs 50 non-blank lines,
including the two-way decodes.

## 3. The arm's derivation and what it consumes

The per-arm equation has Bridge's `Arm` shape:

```
Fof-defSet≡ : (i : Op16) (sub : (v : S) → ⟨ v ∈ˢ Fof i a b ⟩ → ⟨ v ∈ˢ C ⟩)
            → L.defSet (pinned i) ≡ Fof i a b
```

It consumes `Desc.described` (StepGraph.lagda.md:104) with the caller's
`sub`. The caller supplies the subset certificate. The frame performs no
per-op membership analysis. This is exactly the `Arm` contract
(Bridge.lagda.md:170).

The F1 instance mirrors `Describe.F1-defSet≡`
(Describe.lagda.md:499-509):

```
F1-defSet≡ : L.defSet (pinned op1) ≡ F1 a b
F1-defSet≡ = Fof-defSet≡ op1 wsub' ∙ Fof-f1 a b
```

`wsub'` converts `v ∈ Fof op1 a b` to `v ∈ F1 a b` through the delivered
`Fof-f1` (Step.lagda.md:253-254), then reads `v ∈ a` and applies `Ctr`.
`Fof` is `opaque` (Step.lagda.md:229-232), so the `Fof-fk` read lemmas
stand in for Bridge's `reshape` (Bridge.lagda.md:216). The arm consumes
`Layer`'s `memOf`, `memOut`, and `memIn`. It consumes the level-kit
inner semantics. It consumes `Desc.described`, `F1`, `F1-spec`
(Ops.lagda.md:160-166), `Fof`, `Fof-f1`, the fiber machinery, and `Ctr`.
At `op1`, `memOf op1 = mem1`
(StepGraph.lagda.md:1669), `memOut op1 = mem1-out` (:1691), `memIn op1 =
mem1-in` (:1713). The stop-line budget holds: 133 of 150 non-blank lines.
