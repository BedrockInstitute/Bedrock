### The exact bound is what is missing: CONFIRMED, a different object

LevelSigma's prose records the limit clause and the ordinal domain bound as
its omitted pieces (`LevelSigma:20-28`). T61 filled the bound in the
per-component read: `ordDom` (`LevelSigma:581-583`) says every first
component is an ordinal of the carrier, `(a : S) → ∥ Σ b, pr a b ∈ f ∥₁ →
(IsOrd a × ⟨ a ∈ˢ u ⟩)`; its object `domForm` (`:640`) and decodes
(`dom-out`/`dom-in`, `:903`, `:926`) read exactly that. The exact bound is
the tower chapter's `domOrd` (`LevelFormula:139-146`): an existential ordinal
`δ ∈ u` with **both** inclusions, `a ∈ δ → ∃ b, pr a b ∈ f` and
`∃ b, pr a b ∈ f → a ∈ δ`; its formula `domForm` (`LevelFormula:230-239`)
and decodes (`dom-out`/`dom-in`, `:544`, `:592`) were undelivered at the rud
carrier. The difference is load-bearing: the value chain's induction step
needs the totality direction (`# n ∈ δ → ∃ c, pr (# n) c ∈ f`), which the
per-component read drops (T61's own prose: the totality direction is
"deliberately dropped", `LevelSigma:552-556`; T61 report section 1 item 5).
This dispatch ports the exact object: `exactDom` (`LevelSigma:1050`),
`exactDomForm` (`:1084`), `exactDom-out`/`-in` (`:1116`, `:1153`).

### T65's infinite-chain argument: CONFIRMED by reading, before building

The delivered clause is two-way: `succValClause f = (a c b : S) →
⟨ pr a c ∈ˢ f ⟩ → (⟨ pr (sucV a) b ∈ˢ f ⟩ ⟷ powRel c b)`
(`LevelSigma:576-577`), with `_⟷_` both directions (`InitialSegment:78`).
The over-HF identification `powRel-Lset-suc` (`HF:351`) gives
`LA.powRel (Lset ζ) (Lset (sucV ζ))` for `ζ ∈ ω`; the zero clause
(`LevelSigma:128-130`) supplies a memberless `a` with `pr a a ∈ f`, and a
memberless set is `∅` by extensionality, so `pr ∅ ∅ ∈ f`. The induction then
forces `pr (sucVⁿ ∅) (Lset (sucVⁿ ∅)) ∈ f` for every `n` (the ⟸ direction at
`a = # n`, with `#∈ω n` for the identification's hypothesis). The pairs are
pairwise distinct by `pr-inj` (`V.Coding:177`) and `#-inj′` (`:114`). Every
`f ∈ Sset ω` is finite by the in-tree chain: `Sset-union-limit`
(`Bridge:1012`) puts `f` in a finite level `Sset (sucV δ)`, `Sset-trans`
subsets it, `sTally` (`BaseBlock:318`) tallies the level, `subsetTally`
(`HF:102`) tallies `f`; a size-`N` tally cannot hit `N + 1` distinct pairs
(the `notTallyω` pigeonhole pattern, `HF:136`). So the two-way story is
uninhabited at HF and the recorded family equality is false as set up. The
argument is sound; this dispatch builds the repair.
