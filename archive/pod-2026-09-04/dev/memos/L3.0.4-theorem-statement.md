## 1. What the theorem is about

A recursive definition on formulas is internalizable in `L` when the table of its values
is a set of `L`. The source does this eight to ten times by hand; the probe found one
pipeline underneath, and the parameter that varies is a **step specification**.

Informally: fix a family of *indices* (formulas, or pairs of formulas), a *closure*
operation taking an index to the finitely many indices its clauses mention, and an *entry*
map sending an index to the nested tuple that records its value. Give, for each of the
twelve formula constructors, a clause saying what the value at that constructor is in
terms of the values at its subformulas. Then the whole table is a set of `L`.

## 2. The clause bundle

The probe's second finding (`[L3.11]`, S10) is that the twelve tags are traversed five
times per instance. One record collapses the five into one declaration per tag. Stated
over a fixed stage carrier and a fixed bounding predicate:

```agda
record ClauseBundle {n : ℕ} (P : ⟪ Lset σ ⟫ → Type (ℓ-suc ℓ)) : Type (ℓ-suc ℓ) where
  field
    body     : Formula ⟪ Lset σ ⟫ n
    delta0   : Δ₀ body
    bounded  : BoundedFo P body
    sound    : ∀ γ → ⟨ γ ⊨ body ⟩ → Value γ
    complete : ∀ γ → Value γ → ⟨ γ ⊨ body ⟩
```

Every name here is now in Bedrock. `Formula`{.Agda} and the twelve constructors are
`FOL.Syntax`; `Δ₀`{.Agda} is `FOL.LevyHierarchy`; `BoundedFo`{.Agda} is
`FOL.Manipulation.Bounding`, ported for this goal; `_⊨_`{.Agda} is `FOL.Semantics`;
`Lset`{.Agda} and `⟪_⟫`{.Agda} are `L.Constructible` and the library.

`Value` is the instance's own predicate, the thing the clause is *about* (the depth of a
formula, the verdict of a comparison). It is deliberately not a field of the
specification: `sound` and `complete` are where the instance's mathematics lives, and §7
records why the theorem must not try to absorb them.

## 3. The step specification

```agda
record StepSpec : Type (ℓ-suc ℓ) where
  field
    Index      : Type ℓ
    closure    : Index → List Index
    entry      : Index → S
    valueArity : ℕ
    clauses    : Fin 12 → ClauseBundle
    reads      : List (Σ[ t ∈ S ] ⟨ isL t ⟩)
```

Four remarks on the fields.

- **`Index` is `Type ℓ`, not a set of the hierarchy.** It is the meta-level index of the
  table (`Σ[ n ∈ ℕ ] Closed n` for the single-formula instances, the product for the
  comparison instance), and it must be small because `sett` takes a `Type ℓ` family. This
  is the same smallness constraint `L.Definability` already lives under.
- **`closure` returns a `List`.** Finiteness is load-bearing: the witness table for one
  index is a finite `sett`, which is what puts it at a single stage. An infinite closure
  would need a different argument, and no instance has one.
- **`entry` is where `valueArity` is cashed out.** The entry of an index is a nested
  Kuratowski tuple ending in a value numeral, of nesting depth `valueArity`. Stating it as
  a plain function into `S` keeps the theorem free of the tuple's shape; the arity is
  carried separately because the *readers* of §4 are generated from it.
- **`reads` is the field the probe insisted on.** An instance may name an
  already-internalized table as a constant of its clauses (the comparison instance reads
  the depth table). Each entry carries its own `isL`{.Agda} proof, and the theorem's
  bounding step absorbs the stages of all of them. A design without this field passes the
  reference instance and fails the stress instance.

## 4. The theorem

```agda
internalize : (spec : StepSpec) → ⟨ isL (table spec) ⟩
```

where `table spec = sett (Index spec) (entry spec)`.

The proof obligation the specification discharges, spelled as the eight stages the probe
measured, with the Bedrock name that serves each:

| Stage | Discharged by | Bedrock name |
|---|---|---|
| 1 table | `entry`, `Index` | `sett` |
| 2 certificate | `clauses`, assembled by the dispatcher | `Formula`, `_⊨_` |
| 3 Δ₀ and bounding witnesses | `ClauseBundle.delta0`, `.bounded` | `Δ₀`, `BoundedFo` |
| 4 bounding ordinal | stages of the entries and of `reads`, bounded | `boundingOrd`, `Lset-mono` |
| 5 matrix and relabel | generic, from `valueArity` | `liftFo` (`[L2.2]`) |
| 6 ⊆-soundness | `ClauseBundle.sound`, per tag | instance data |
| 7 ⊇-witness | `closure` gives the finite table; satisfaction from `.complete` | `finSettAtLevel` (`[L3.2]`) |
| 8 closure | generic | **`defSet→isL`** |

Stage 4 and stage 8 are already Bedrock theorems, from `[L2.0]` and `[L2.1]`: this is the
first concrete sign that the constructive foundation laid there is the right substrate,
since the bounding ordinal is exactly what stage 4 needs and it costs no assumption.
Stages 5 and 7 name the two pieces still to be ported; stage 2's dispatcher is `[L3.11]`.

## 7. What the theorem does not claim

Three limits, stated so that `[L3.0.1]` is judged against them rather than against a
wish.

1. **It does not absorb soundness.** `Cmp` and `Depth` agree at 8% precisely in their
   soundness segments: one recurses on a formula producing a numeral, the other on a pair
   producing a three-valued lexicographic verdict. `sound` and `complete` are instance
   data, and a proof of concept that claims otherwise has mis-stated the theorem.
2. **It does not discharge instance hypotheses.** `cmpGraphV∈L'` is delivered upstream as
   unconditional-modulo-`wcCert`, a module hypothesis that the merged two-code witness
   table satisfies the code certificate. In Bedrock that is a Frontier field belonging to
   the instance, and the theorem must leave it standing.
3. **It does not cover transfinite recursion.** The table is one constant `sett`. A
   recursion whose graph is ordinal-indexed and reads itself (`Order*`) is a different
   theorem, registered as `[L3.12]`, and gated on this one landing because the order
   certificate names the comparison table as a constant leaf.

## 7a. Amendments from the phase-C re-evaluation (2026-07-25, after `[L2.2]`)

Two corrections to the above, recorded here rather than by rewriting the sections they
correct.

1. **Stage 7's prerequisite is not `[L3.2]`.** §4's table names `finSettAtLevel`
   (`[L3.2]`). That lemma is not macro work: it says a finite family drawn from a stage is
   a set of `L`, and it is about sixty lines by finite disjunction over the stage's index
   type. It is now `[L3.0.5]`, delivered as `FinOf.finSetL` in `L.Axioms.Basic`, where it
   generalizes that chapter's hand-written pairing. `[L3.2]` leaves this theorem's
   critical path.
2. **`reads` must carry sealed certificates.** §3's
   `reads : List (Σ[ t ∈ S ] ⟨ isL t ⟩)` is a list of sets paired with constructibility
   certificates, used as constants of the clauses' object language. That is exactly the
   shape that cost `L.Axioms.Full` ten minutes of conversion checking until the
   certificate was sealed at its construction site (`opaque isL-Lset`), after which the
   chapter took 1.4 s. Any instance supplying `reads` must seal likewise, and the
   theorem should be written so that it never needs those certificates to reduce.

One remark on §8's design risk, which is now weaker than when written. The hazard cited
(source WORKLOG case 13: a twelve-field record of formula-valued fields failing to
typecheck) is answered by `L.ReflectFo`, which carries a twelve-clause tree, its
twelve-clause raise, and a twelve-clause recursion returning a Σ-package of an ordinal
with its witnesses, all checking in about two seconds. The record route is viable here;
the Π-parameterization fallback stays available but is no longer the expected outcome.

## 7b. Superseded (2026-07-25, same day)

Sections 2 to 6 above describe a theorem that Bedrock does not need. `L.Recursion`
delivers the conclusion in 52 lines of Agda as a wrapper around `hasReplacementL`.

The eight-stage pipeline exists in the source because the source's comprehension fields
are Δ₀-only, so a table has to be made definable *inside a stage*, where a formula does
not mean what it means outside. `[L2.2]` removed that constraint: replacement in `L`
holds for formulas of any complexity and is read at the class model. Stages 1 to 5, 7 and
8 therefore have nothing to discharge, `StepSpec` reduces to a domain, a graph and
single-valuedness, and `ClauseBundle` loses `delta0` and `bounded`.

§7's three non-claims survive unchanged and are now the whole remainder: the theorem does
not absorb soundness, does not discharge instance hypotheses, and each instance still owes
an index set in `L`. §8's recommendation is withdrawn; see PLAN §11 for the re-scoping of
`[L3.11]`, `[L3.12]` and `[L3.13]`.

## 8. Recommendation to the gate (withdrawn, see 7b)

Proceed to `[L3.11]` (the clause bundle) and then `[L3.0.1]`, in that order, per §6.1
phase C. The bundle is the cheaper half of the mass and the honest de-risk for the
theorem: a bundle that cannot be built without conversion blowup predicts a theorem that
cannot either, and it is worth taking on a red verdict anyway.

The one design risk worth naming at the gate: `StepSpec` is a record of twelve
`ClauseBundle`s, each carrying a `Formula` over a stage-indexed constant domain. The
source's WORKLOG §5 case 13 records a twelve-field record of formula-valued fields
failing to typecheck at all, the fix being Π-parameterization instead of a record. If the
same happens here, `StepSpec` becomes a module telescope rather than a record, and the
statement above should be read as the interface rather than the literal declaration.
