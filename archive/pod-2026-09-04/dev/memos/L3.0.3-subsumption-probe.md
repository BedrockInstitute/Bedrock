# [L3.0.3] Subsumption probe: does one step specification subsume `Cmp*` and `Depth*`?

Deliverable of goal `[L3.0.3]` (PLAN §6.1). Source-reading only, against
`../fol-reification` at the pinned commit `8b190d5`; no `src/` file was touched.
Developer doc, English only.

**Verdict: amber. The central question answers yes; the projected payoff does not
survive measurement.** One step specification does subsume `Cmp*` and `Depth*`, and
`FFST*` is already a third instance of the same shape, so D12's route is alive and
`[L3.0.4]` should proceed. But the harness that a pipeline theorem absorbs is 4,673
lines across the three instances, not the 8k to 12k that PLAN §2.1 projected. The rest
of the mass is per-tag clause work and genuine per-instance mathematics, which need a
*second* abstraction and a *third* theorem respectively. §6 restates the projection.

## 1. The shape the three instances share

`FFST∈L'`, `depthGraphV∈L'` and `cmpGraphV∈L'` are the same eight-stage pipeline. The
source knows this and says so in its own prose (`L.DepthGraph` calls itself "the third
instance of the FFST∈L' engine", `L.CmpGraphInLFinal` calls itself "a faithful clone of
`L.DepthGraphInLFinal`"), and it reuses named generic pieces across all three:
`metaφ⟹isL'`, `bridgeExpand`, `matrixLeg`, `subBridge`, `finSettAtLevel`, `subClosure`,
`entryShapeWit-gen`. What it never does is parameterize the pipeline itself.

| # | Stage | What it produces | Instance-specific? |
|---|---|---|---|
| 1 | Table | a constant V-set of entries, entry = nested `pr` tuple ending in a value numeral | entry arity |
| 2 | Certificate | Δ₀ formula verifying each entry: shape readers plus one clause per tag | **yes, the clause family** |
| 3 | Bounding witness | `BoundedFo Pσ` for the certificate, leaf by leaf | no, follows the clause family |
| 4 | Bounding ordinal | `boundingOrd` over a sum family absorbing entry stages, numerals, ω, and any constant table the certificate reads | no |
| 5 | Matrix and relabel | `matrix = Cert{2} zero ∧̇ (var₁ ∈̇ var₀) ∧̇ link`, `liftFo` to `⟪Lσ⟫`, `φ = ∃̇ matrix⟪⟫` | no |
| 6 | ⊆-soundness | any `W` satisfying the certificate assigns the true value to genuine-code entries | **yes, this is the mathematics** |
| 7 | ⊇-witness | a finite table `W_of` (subformula closure) satisfying the certificate and landing in `Lset σ` | table generic, satisfaction **yes** |
| 8 | Closure | `defSet≡` then `metaφ⟹isL'` | no |

Stages 3, 4, 5 and 8 are pure harness. Stage 1 and 7's table construction are harness
parameterized by an index type. Stages 2, 6 and 7's satisfaction proof are where the
instances genuinely differ.

## 2. Proposed step specification

The signature that makes stages 1, 3, 4, 5, 7-table and 8 generic:

```
record StepSpec where
  Index      : Type                       -- FFST: Σ[n] Closed n;  Cmp: Σ[n] (Closed n × Closed n)
  closure    : Index → List Index         -- subformula (or sub-pair) closure, closed under direct subterms
  entry      : Index → V                  -- the nested pr tuple
  valueArity : ℕ                          -- entry nesting depth: FFST 2, Depth 3, Cmp 4
  clauses    : (tag : Fin 12) → ClauseBundle
  reads      : List InternalizedTable      -- constant tables the certificate may name (Cmp reads depthGraphV)
```

with the per-tag `ClauseBundle` carrying, for one tag, the five artifacts the source
currently spreads over five modules:

```
record ClauseBundle where
  body      : Formula _ k                 -- the tag's recursion clause
  delta0    : Δ₀ body                     -- Levy witness
  bounded   : BoundedFo Pσ body           -- leaf-by-leaf bounding witness
  sound     : satisfies body → true-value  -- the ⊆ direction for this tag
  complete  : true-value → satisfies body  -- the ⊇ direction for this tag
```

Theorem to prove once: a `StepSpec` yields `⟨ isL' (table spec) ⟩`, given the bundle's
`sound` and `complete` per tag. The clause bundle is not decoration; §5 shows it is
where most of the recoverable mass actually sits.

## 3. Subsumption check: the twins as instances

| Specification field | `Depth` fills with | `Cmp` fills with |
|---|---|---|
| `Index` | `ClosedΣ = Σ[n] Closed n` (reused from FFST verbatim) | `CmpIdx = Σ[n] (Closed n × Closed n)`, the product closure |
| `closure` | `subClosure` (FFST's, verbatim) | sub-pair closure: descend to child pairs at equal tag, singleton otherwise |
| `entry` | `pr (# n) (pr ⌜embed φ⌝ (# depthF φ))` | `pr (# n) (pr ⌜embed φ⌝ (pr ⌜embed ψ⌝ (# verdict3 φ ψ)))` |
| `valueArity` | 3 | 4 |
| `clauses` | leaf `d ≐ # 2` / `# 1`, unary `succAt`, binary `succMaxAt`, bounded `succMaxAt` with left `# 1` | six legs: depth, tag, children, eq, and their inverses, dispatched by `triD` |
| `reads` | none | `depthGraphV` (the cmp certificate reads two codes' depths through `con depthGraphV`) |

Every field is fillable, and no field is left over. The clone measurement supports it
from the other side: after renaming, `CmpCertMatrix`/`DepthCertMatrix` agree at 86%,
`CmpCodeCarrier`/`DepthCodeCarrier` at 67%, `CmpGraphInL`/`DepthGraphInL` at 60%,
`CmpGraphInLFinal`/`DepthGraphInLFinal` at 50%. Those four pairs are exactly stages 3,
4, 5 and 8.

**The `reads` field is load-bearing and easy to miss.** Cmp's certificate names
`depthGraphV` as a constant, so the specification must let an instance depend on a
previously internalized table, and the bounding ordinal of stage 4 must absorb that
table's own bounding ordinal. Any design that treats instances as independent will fail
on the second one.

## 4. Where the twins diverge, and why the theorem must not absorb it

`CmpSound` and `DepthSound` agree at 8% after renaming. That number is not noise:

- **Depth** recurses on one formula and produces one numeral, `d = 1 + max(d₁, d₂)`.
  Its only new object brick is `succMaxAt` (200 lines) with a two-way numeral adequacy.
- **Cmp** recurses on a *pair*, produces a three-valued verdict, and must invert the
  second formula from its code. Its verdict is `lex(depthF, lex(tagN, sameTagLex))`, so
  soundness needs a whole module of lex bridges (`CmpVerdictBridge`) and per-tag
  soundness legs (`CmpSoundAtom/Bin/Un/Bnd/Row/Clash/Main`).

A specification that claimed to absorb soundness would have to absorb "the recursion is
a lexicographic order on pairs" as a special case of "the recursion is `1 + max`", which
is false. `sound` and `complete` stay instance data. This confirms the constraint PLAN
§6.1 already writes into `[L3.0.4]`.

One further honesty item for `[L3.0.4]`: `cmpGraphV∈L'` is delivered
**unconditional-modulo-`wcCert`**, a module hypothesis (that the merged two-code
witness table satisfies the FFST certificate), not a postulate and not a hole. Depth
closes unconditionally. In Bedrock that hypothesis is a Frontier field, not a debt of
the theorem, and the specification must not silently discharge it.

## 5. Measured mass, by role

Splitting the three instances by module role (H = pipeline harness, M = instance
mathematics), in non-blank code lines:

| Instance | harness | instance mathematics | total |
|---|---:|---:|---:|
| `Cmp*` | 1,550 | 5,522 | 7,072 |
| `Depth*` | 1,578 | 1,824 | 3,402 |
| `FFST*` | 1,545 | 0 | 1,545 |
| **sum** | **4,673** | **7,346** | **12,019** |

So the pipeline theorem's direct target is the 4,673 lines written three times over. A
generic module plus three thin instantiations plausibly lands near 1,800, saving about
**2.9k**.

The larger recoverable block is inside the instance mathematics, and it is not the
mathematics itself. Cmp spends 3,130 lines on per-tag work spread across seven soundness
modules and `CmpWitnessSat` (1,473), and `CmpWitnessSat` is the module the source's own
WORKLOG case 19 diagnoses as "132 of 144 clauses carry zero mathematical content". The
same twelve tags are traversed five times per instance: once for the clause formula,
once for its Δ₀ witness, once for its bounding witness, once for soundness, once for
witness satisfaction. The `ClauseBundle` of §2 is what collapses those five traversals
into one declaration per tag, and it is worth roughly as much again as the pipeline
theorem.

## 6. Revised projection, correcting PLAN §2.1

PLAN §2.1 projected that the theorem would "collapse the 8 to 10 pipelines into one
theorem plus small instances, putting the certificate mass in the 8k to 12k range". The
probe does not support that number. Corrected picture, over the 42,258 exclusive lines:

| Tier | Families | Lines | Status after this probe |
|---|---|---:|---|
| 1 | `Cmp*`, `Depth*`, `FFST*`, `CodeSeq*`, `SubBridge` | 13,518 | **fits** the constant-table theorem; harness 4.7k plus per-tag work 4.4k are addressable, saving roughly 5k to 7k with the clause bundle included |
| 2 | `Order*`, `Trace*`, `Canon*`, `Env*` | 11,386 | **does not fit**: needs a second, stage-indexed theorem (§7) |
| 3 | `Sat*`, `Tarski*`, `Coh*` | 10,706 | **partial**: certificate half fits, table half does not (§7) |
| 4 | `CodeOrder`, `Choice*`, `Lset*`, `Well*`, `Def*`, and the rest | 6,648 | not pipeline; instance mathematics, closure tower, endgame |

Reaching PLAN §2.1's 8k to 12k would require all three theorems plus the clause bundle.
On tier 1 alone the honest projection is 42.3k to about 36k. That is still the largest
single lever measured, and it is still worth taking, but D12's "roughly 65%" should be
read as the ceiling of a three-theorem programme, not the yield of `[L3.0]`.

## 7. Fits classification for the remaining families

- **`Order*` (7,867): does not fit, needs its own theorem.** `G_ord` is not a constant
  table. Its certificate's env comparison reads the graph itself (`lookupLt`), the graph
  is ordinal-indexed (`G_true@α`) and built by transfinite recursion, and closure is by
  ∈-induction with a successor/limit dispatch under LEM. The source states the obstacle
  directly: an object formula is finite while the env recursion is transfinite
  (`L.OrderGraphG`, "V-32 #3"). Its image construction goes through `hasRepl` rather than
  finite `mkSett` tables. The right shape is a **second theorem**: a transfinite
  recursion whose step is internalizable yields an internalizable ordinal-indexed
  family. Recommend registering it as its own goal rather than widening `[L3.0]`.
- **`Sat*`, `Coh*`, `Tarski*` (10,706): partial.** They share stages 2, 6, 7 and 8 but
  not stage 1: the total clause's only witness for `satSet` is `satSet` itself, which is
  circular, so the source switched to a `(C,S)`-pair *partial* certificate carrying a
  downward-closed code set (`L.CohCert`). The certificate half of the theorem applies;
  the constant-table half does not. Revisit after tier 1 lands, with the partial
  certificate as a variant of the specification rather than a new theorem.
- **`Trace*`, `Canon*`, `Env*` (3,519): follows `Order*`.** The trace matrix is keyed by
  ordinals and exists to feed the order graph; it moves with tier 2.
- **`LsetClosure`, `SeqSetInL`, `Seq*` (roughly 1,078): no theorem needed.** These are
  already served by `metaφ⟹isL'` plus the closure lemma tower, which is the existing
  shared engine and is small. Port as is.

## 8. Required-interface checklist

What the theorem consumes, and the shape it needs it in. This is the part `[L2.2]` and
`[L3.3]` must honour, since porting these in the wrong shape is what forces the
re-derivation the theorem is meant to remove.

**Already landed (L1):** `FOL.LevyHierarchy` Δ₀ witnesses; `FOL.Absoluteness`;
`L.Definability` (`Def`, `defSet`); `L.Constructible` (`isL`, `Lset`, `IsOrd`,
`Lset-layer`); `V.Hierarchy.∈-induction`.

**Needed, with shape requirements:**

1. **Codes as an inductive relation.** `ZF.Coding.Codes` with `mkTag`, `tagN`, `⌜⌝-inj`,
   `embed-inj`. Code *values* must never appear as the endpoints of a path that Agda
   normalizes; WORKLOG §5 case 12 measured over 100 s and 10 GB on one such equality.
   Port the relation first and the values as opaque.
2. **Object-level Δ₀ readers with adequacy**, parameterized over de Bruijn position from
   the start: `sglAt`, `pairAt`, `prAt`, `tagAt`, `unpairAt`, each with its `-adequate`
   lemma. Currently `L.SatCertBase` and `L.TraceMat`.
3. **`BoundedFo` / `BoundedTm` plus `Relabel.liftFo` and `liftFo-correct`** (`[L2.2]`).
   Every `liftFo`-family call site must pass its formula index explicitly (`{φ = ...}`);
   WORKLOG case 16 measured 74 minutes on one module from a single implicit here.
4. **`metaφ⟹isL'`**, the closure engine. It currently lives inside `L.ChoiceSetInL`,
   which is the wrong home: it is used by the whole closure tower. In Bedrock it belongs
   in an early `L.Closure` chapter, before any consumer.
5. **Domain-change infrastructure**: `bridgeExpand`, `matrixLeg`, and the bridge
   instantiation currently called `ProbeM1Bridge`. The name is provenance-flavoured and
   dies under D7; the content is generic and should be minted as such.
6. **Closure-table kit generic over the index type from day one**: `subClosure`, `W_of`,
   `entryOf`, `nthEntry`, `W_of-elim`, `entryShapeWit-gen`. The source already factors
   entry construction through an index (`ClosedΣ`), so this is a small step, but Cmp's
   product index proves the genericity is required rather than speculative.
7. **Level bricks**: `finSettAtLevel`, `unionAtLevel`, `isL'-pr`, `isL'-num`,
   `isL'-finSett` (`L.LsetClosure`).
8. **`boundingOrd` plus `stage` / `stage-ord` / `stage-mem`** (LEM cone), and a
   **reusable bounding-ordinal lemma**: every instance builds σ by `boundingOrd` over a
   sum family absorbing entry stages, numerals, ω, and read tables. Factor it once.
   Seal the resulting ordinal `opaque` at the point of definition; WORKLOG case 20b
   measured a transparent bounding ordinal taxing every downstream `⟨ _ ∈ Lset τ ⟩`.
9. **`subBridge`**, the truncated decode by ∈-descent on code values. Its statement is
   generic already; its consumers (`linkClause`, one code or two) are the instance's.

## 9. Recommendations for `[L3.0.4]`

1. State the theorem with **both** abstractions in the signature: the pipeline
   parameterization and the per-tag `ClauseBundle`. They compose (the bundle is the
   `clauses` field), and §5 shows the bundle carries roughly half the recoverable mass.
2. Take `Depth` as the reference instance and `Cmp` as the stress instance. `FFST` is
   the degenerate case (no instance mathematics at all) and will not exercise the
   signature.
3. Carry the `reads` field from the first draft. Cmp needs it; a design without it
   passes the reference instance and fails the stress instance.
4. Do not let the theorem discharge `wcCert`. It is a genuine hypothesis of the cmp
   instance and belongs in the Frontier.
5. Register the stage-indexed theorem for `Order*` as a separate goal before `[L3.5]`
   is scheduled, so that tier 2 is not silently assumed to be covered.
6. Amend PLAN §2.1's projection to the tier table of §6, so the plan does not carry a
   number this probe has already contradicted.
